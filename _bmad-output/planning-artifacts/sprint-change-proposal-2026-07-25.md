# Sprint Change Proposal (2026-07-25)

> 병원 진료관리(hospital-care) — Epic 3 done 직후, Epic 4(조회) 착수 전 시점의 방향 추가.
> 승인 완료(2026-07-25, Incremental 모드). 규모: **Moderate(백로그 재편)**.

## 1. 이슈 요약 (Issue Summary)

**트리거:** 신규 요구(stakeholder) — 진입 역할 모델을 재구성한다.

기존 2역할(환자/직원)에 **의사**를 독립 역할로 추가하고, 직원 화면을 좌측 사이드바 셸로 재편한다:

- **의사**: 진입 시 어떤 의사인지 선택 → 그 의사에게 **배정된 예약이 먼저** 보인다. 진료가 완료되면 자동으로 "완료된 진료"로 분류되어 배정 예약 목록에서 사라진다.
- **직원**: 예약관리가 가장 크게 보이고, 직원이 **스스로 예약을 잡을 수 있다(대리 예약)**. 좌측에 bar 형태 사이드바 — 예약관리 + 신규 환자 등록 + 환자 목록·검색(현재 직원 홈의 카드 3장 재배치).

구현 중 발견된 결함이 아니라 방향 추가다. 되돌릴 완료 작업이 없고 전부 **가산(add-only)**, **DB 마이그레이션 0건**.

**발견 경위:** Epic 3 회고 완료 후 `/bmad-help` → `/bmad-correct-course`로 사용자가 직접 제기.

### 아티팩트 충돌

**🟢 아키텍처 — 거의 무영향 (핵심 de-risk).**
- 예약은 이미 `doctor_id`가 항상 채워짐(FR-6 P0), 완료 전이도 이미 존재(FR-8).
- "의사별 배정 예약, 완료 제외" = `GET /appointments?doctor_id=&status=대기,확정` 필터 하나. **신규 스키마 없음**, AD-8(환자 `?patient_id=` 앱 레벨 필터)의 의사판일 뿐.
- "직원 대리 예약" = 기존 Epic 2 예약 폼(FR-6 P0)을 직원 측에서 재사용.

**🟡 PRD** (`prd.md`): FR-1 수정(+의사), FR-1b/FR-17/FR-18 추가, §3 User Journey 전제 개정·의사 페르소나 승격.

**🟡 UX** (`DESIGN.md` + epics.md UX 인벤토리): UX-DR4(역할 컨텍스트 바)에 의사 수용, UX-DR12(직원 좌측 내비 셸) 추가, §Layout 개정.

**🟢 백엔드/DB:** 마이그레이션·스키마 변경 없음. 라우터에 `?doctor_id=` 필터 옵션·직원 예약 생성 경로만 add-only.

### 기술 영향
- 프런트: 신규 라우트 `/doctor`, `/doctor/select`(또는 컨텍스트), 의사 대시보드; 직원 앱 셸 사이드바; 직원 예약 폼 진입.
- 백엔드: `GET /appointments`에 `doctor_id`·`status` 필터, 직원 대리 예약 생성(기존 `POST /appointments` 재사용).

## 4. 상세 변경 제안 (Detailed Change Proposals)

### 4-1. PRD (`prds/prd-hospital-care-2026-07-12/prd.md`)

**FR-1 수정**
```
OLD: FR-1 첫 화면에서 사용자는 [환자] / [직원] 역할을 선택한다. (실제 로그인 없음)
NEW: FR-1 첫 화면에서 사용자는 [환자] / [직원] / [의사] 역할을 선택한다. (실제 로그인 없음)
```

**FR-1b 추가 (의사 진입)** — F1 절
> `[의사]` 선택 시 의사 목록에서 본인을 고른다(FR-2 환자 신원 선택의 의사판 — 로그인 대체, 기밀 격리 아님). 이후 의사 화면은 그 의사에게 배정된 예약을 먼저 보여준다.

**FR-17 추가 (의사 배정 예약 뷰)** — F3 절
> 의사 화면은 배정된 활성 예약(대기·확정)을 먼저 보여주고, 진료 기록 작성으로 완료 전이된 예약은 활성 목록에서 빠져 "완료된 진료"로 분류된다. `GET /appointments?doctor_id=&status=…` 필터(AD-8의 의사판) — 신규 스키마 없음.

**FR-18 추가 (직원 대리 예약)** — F3 절
> 직원이 예약 관리에서 환자를 골라 예약 폼(FR-6 P0 재사용)으로 대리 예약을 생성한다. walk-in 즉시진료(FR-16, Epic 5.3 P1)와 구분한다.

**§3 User Journey 수정**
> "로그인이 없으므로 의사도 `[직원]` 화면 안에서 진료 기록을 작성한다" 전제 → 의사는 `[의사]` 역할로 독립 진입한다. 👨‍⚕️김민재를 직원의 서브 페르소나에서 **독립 역할로 승격**. UJ-3(의사가 자기 배정 예약을 열어 진료·기록) 추가.
