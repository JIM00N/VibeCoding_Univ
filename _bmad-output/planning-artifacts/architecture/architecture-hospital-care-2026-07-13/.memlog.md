- (constraint) [상속·NFR-3] 스택 확정: Next.js(프런트) → FastAPI(Python 백엔드) → Supabase(PostgreSQL). 브라우저는 Supabase를 직접 호출하지 않고 FastAPI만 호출한다. 재결정 대상 아님.
- (constraint) [상속·FR-1~3] 로그인 없음. 첫 화면 역할 선택(환자/직원). 환자는 목록에서 본인 선택(신원). 직원은 전체 접근. '기밀 격리 아님' — 데모 전제.
- (constraint) [상속·A1/NFR-4] 보안 posture: 9개 테이블 전부 RLS ON, anon 역할 허용정책 미생성(deny-by-default). 모든 DB 접근은 FastAPI가 서버측 키(service_role)로만. 서버키는 환경변수, 프런트 번들 금지. 환자별 격리는 API 레벨 필터(patient_id).
- (constraint) [상속·A4] 가용성 단위=(의사, 30분 슬롯). 예약 reserved_at은 슬롯 경계, walk-in visited_at은 슬롯으로 floor. 충돌 소스 2개(교차테이블): appointment(대기·확정) ∪ walk-in medical_record(appointment_id null). 충돌검사는 앱(FastAPI) 레벨, 단일세션 전제 보장(TOCTOU 범위밖).
- (constraint) [상속·A3] 데이터모델: 9테이블 정규화 유지. medical_record가 hospital_department_id 자체보관(이력 불변). medical_record.doctor_id NOT NULL. appointment.doctor_id는 DB nullable이나 앱이 항상 채움(2계층). 부분유니크 uq_medical_record_appointment(appointment_id where not null). reserved_at 30분정렬 CHECK.
- (constraint) [상속·NFR-1/A2] 배포 Railway 필수, 공개 URL 시연. 초반에 배포 뼈대부터. RLS 마이그레이션을 배포 뼈대와 함께 P0 초기 산출물로.
- (constraint) [상속·프로젝트] 1인 개발, 마감 2026-07-16(목,+3일). 성공=핵심 한줄기 E2E(등록→의사직접선택 예약→확정→기록→조회)가 배포URL에서 관통 + 9테이블 RLS ON. 넓이보다 관통 우선.
- (event) 입력(brief/prd/addendum) 로드 완료. 스택·보안·가용성·데이터모델 상속 확정. 코드 아직 없음(그린필드). db-design/schema.sql은 레포에 없고 Supabase(fphsxoweprztrekckzui)에 배포됨.
