# hospital-care — Experience Spine

> *어떻게 동작하는가*를 소유한다(시각은 `DESIGN.md`). PRD 여정·아키텍처 스파인(AD-*)을 출처로 상속. (확정 2026-07-13)

## Foundation

**반응형 웹**, 로그인 없음. shadcn/ui on **Next.js App Router + Tailwind** (확정 2026-07-13) — 컴포넌트 라이브러리가 일을 대부분 한다. `DESIGN.md`가 시각 정체성 참조.

- **두 역할 컨텍스트**(환자/직원)를 첫 화면 **역할 선택**으로 가른다(인증 대체, 아키텍처 AD-1 상속). 직원=전체 접근, 환자=선택된 본인 데이터만(단, **기밀 격리 아님** — AD-8).
- **밀도:** 직원=데스크톱 우선(밀도 있는 표), 환자=모바일 친화 단일 컬럼.
- **데이터는 오직 FastAPI 통해**(브라우저→FastAPI 직접, AD-1). 프런트는 **단일 API 클라이언트 `lib/api.ts`** 하나로만 호출(AD-10). 저장은 **비관적**(서버 확정 후 반영) — 슬롯 충돌 검사 때문.

## Information Architecture

| 화면(Surface) | 도달 경로 | 목적 |
|---|---|---|
| **역할 선택** `/` | 앱 진입 | 환자 / 직원 택1 |
| **환자 신원 선택** | 역할선택→환자 | 등록 환자 목록에서 본인 선택(데모 고지). 이후 이 환자로 컨텍스트 고정 |
| **환자 홈** | 신원 선택 후 | 내 예약 목록(상태 배지) + 지난 진료 기록(진단·처방) + "예약 잡기" CTA |
| **예약 잡기** | 환자 홈 CTA | 진료과 → 담당 의사 → 날짜 → **슬롯 피커** → 확인 (P0: 의사 직접 선택) |
| **직원 홈** | 역할선택→직원 | 오늘 예약 요약 + 바로가기(환자 등록·예약 관리·조회·walk-in) |
| **환자 등록** | 직원 홈 | 신규 환자 폼(이름 필수·생년월일·성별·연락처) |
| **환자 목록/검색** | 직원 홈 | 이름 검색 → 환자 상세로 |
| **예약 관리** | 직원 홈 | 예약 목록(상태별). 행 액션: 확정 · 취소 · 의사 변경 |
| **진료 기록 작성** | 예약 관리의 *확정* 예약 행 | 진단·소견·진료일시 + **처방 0..N행**. 저장 시 예약 완료 전이 |
| **환자별 조회** | 환자 상세 / 예약관리 | 그 환자의 예약·진료·처방 전체 이력 |
| **walk-in 환자 접수** `(P1)` | 예약 관리 → 대리 예약 | 진료과 선택 → 담당 의사 **"자동 배정"** + **"가장 빠른 시간"** → 접수. 전원 점유면 거부. *(2026-07-28 correct-course — 전용 화면 없음, 대리 예약 폼이 흡수)* |

**IA 닫힘 확인:** PRD의 모든 요구(등록·예약·확정·기록·조회·walk-in)가 위 화면 중 하나에 안착하고, 각 화면은 도달 경로가 있다. 모달은 1단계까지만(확정 다이얼로그 위에 또 다른 모달 금지).

→ 구성 참조(핵심 화면 목업, 렌더 검증됨): [`mockups/booking.html`](./mockups/booking.html)(예약 잡기·슬롯 피커), [`mockups/record.html`](./mockups/record.html)(진료 기록 작성·완료 전이). 나머지 화면은 spine-only(위 표로 빌드). **스파인이 목업과 충돌 시 스파인 우선.**

## Voice and Tone

microcopy. 브랜드 보이스·미감은 `DESIGN.md`.

| Do | Don't |
|---|---|
| "이수민님, 안녕하세요" (환자, 해요체·안심) | "환영합니다 고객님!" (과장) |
| "예약이 확정되었어요." | "예약이 성공적으로 처리되었습니다 ✓" |
| "이 시간엔 김민재 선생님 예약이 이미 있어요. 다른 시간을 골라주세요." (정직·실행가능) | "오류가 발생했습니다." (막연) |
| "지금 이 진료과엔 빈 의사가 없어요. 다른 시각에 다시 시도해 주세요." (walk-in 거부) | "처리할 수 없습니다." |
| 직원=간결한 동사·수치("오늘 예약 8건"), 환자=안심되는 문장 | 환자에게 직원용 축약어 노출 |
| **데모 고지:** "지금은 로그인이 없어 누구나 목록에서 환자를 고를 수 있어요(데모)." | 데모 한계를 숨겨 진짜 보안인 척 |

## Component Patterns

행동 규칙. 시각 스펙은 `DESIGN.md.Components`(또는 shadcn 기본).

| 컴포넌트 | 사용처 | 행동 규칙 |
|---|---|---|
| **Role Context Bar** | 전역 상단 | 현재 역할 + 선택 환자명 표시. "역할 바꾸기"·"다른 환자" 액션. 새로고침해도 컨텍스트 유지(로컬 상태/URL). |
| **Status Badge** | 예약 목록·환자 홈·조회 | `appointment.status` 4값을 색+한국어 텍스트로. 어디서나 같은 매핑(DESIGN 상태색). |
| **Slot Picker** | 예약 잡기, (P1)walk-in | 진료과→의사→날짜 고르면 그 (의사, 날짜)의 **30분 슬롯 격자** 표시. `taken` 슬롯은 disabled + "예약됨". 선택 시 highlight. **서버가 가용성의 진실**이라 제출 시 재검증 — 충돌 나면 그 슬롯을 taken으로 갱신하고 안내. |
| **Confirm Dialog** | 예약 취소 등 파괴적 액션 | shadcn Dialog. "정말 취소할까요?" + destructive 확인. 되돌릴 수 없음 명시. |
| **환자 검색** | 환자 목록 | 이름 입력 → 즉시 필터(디바운스). 결과 행 클릭 → 환자 상세. |
| **Prescription Row Repeater** | 진료 기록 작성 | 약 선택 + 용법·용량 + 일수 한 행. "+ 처방 추가"로 행 추가, 각 행 삭제 가능. 0개 허용. |
| **진료 기록 폼** | 진료 기록 작성 | 대상 예약이 **확정**일 때만 진입(AD-5). 저장 성공 시 그 예약 배지가 즉시 **완료**로 바뀌는 걸 보여줌. |

## State Patterns

| 상태 | 화면 | 처리 |
|---|---|---|
| 로딩 | 목록/조회 | shadcn `Skeleton` 행. 데이터 오면 대체. |
| 빈 상태 — 내 예약 없음 | 환자 홈 | display: "아직 예약이 없어요." + "예약 잡기" 버튼. |
| 빈 상태 — 기록 없음 | 환자 홈·조회 | "지난 진료 기록이 없어요." |
| 빈 상태 — 환자 없음 | 환자 목록 | "등록된 환자가 없어요. 새 환자를 등록해 주세요." + 등록 버튼. |
| 성공 | 저장/확정 후 | shadcn `Toast`: "저장했어요" / "예약이 확정되었어요". |
| 일반 오류 | 전역 | API 실패 시 `Toast`(destructive): "잠시 문제가 생겼어요. 다시 시도해 주세요." |
| **도메인 거부 — 슬롯 충돌** | 예약·의사변경·walk-in | red 인라인/`Toast`: "이 시간엔 이미 예약이 있어요." + 슬롯 피커에서 해당 슬롯 taken 갱신. (아키텍처 AD-4) |
| **도메인 거부 — 전원 점유(walk-in 접수)** | 대리 예약 `(P1)` | red **인라인**(슬롯 충돌과 동일 처리로 수렴 — 2026-07-28 correct-course, 전용 화면이 없어져 Dialog 가 불필요해짐): "이 시간엔 모든 의사의 예약이 차 있어요. 다른 시간을 골라 주세요." + 그 셀 taken 갱신 → 종료(대기열 없음, PRD FR-16). |
| 데모 고지 | 환자 신원 선택 | 안내 배너(파괴적 아님): 로그인 없음·기밀 격리 아님(AD-8). |

## Interaction Primitives

**마우스/터치 우선, 완전 키보드 접근 가능**(Drift 같은 키보드-퍼스트 아님 — 일반 청중 폼 앱).

- 클릭/탭으로 액션, 폼 제출은 명시적 버튼.
- **인라인 검증**: 필수값(환자 이름, 예약 의사/슬롯) 미입력 시 제출 전 필드 옆 안내.
- `Toast`는 비차단, `Dialog`는 1단계까지.
- **금지**: 무한 스크롤(페이지네이션/간단 목록), hover-only 액션(모바일), 2단계 이상 모달, 색만으로 상태 표시.

## Accessibility Floor

행동. 시각 대비는 `DESIGN.md`(shadcn AA 기본 + 브랜드 override 대비 확인).

- WCAG 2.2 **AA**, 반응형 웹 전반.
- 모든 입력에 `<label>`(연락처·생년월일·약·용량 등). 슬롯 피커 셀은 접근 가능한 이름("7월 14일 10:30, 예약 가능/예약됨").
- 상태는 **색만이 아니라 텍스트로도**(배지 한국어 병기).
- `Tab` 순서 = 읽기 순서. 포커스 링(shadcn `ring`) 항상 보임. `Esc`로 모달 닫힘.
- 한국어 스크린리더 라벨. `Toast`는 `aria-live`로 읽힘.

## Responsive & Platform

| 브레이크포인트 | 동작 |
|---|---|
| `≥ md`(768px+) | 직원 예약/환자 목록은 밀도 있는 **표**. 역할 컨텍스트 바 가로. |
| `< md`(모바일) | 표는 카드 리스트로 접힘. 환자 화면은 단일 컬럼. 슬롯 피커는 2~3열 격자. |

환자 흐름은 폰에서 읽기+예약까지 되고, 직원 흐름의 주 무대는 데스크톱/랩톱.

## 무인증 데모 어포던스 (invented)

로그인이 없다는 사실을 **정직하게 다루는** 것이 이 제품의 고유 관심사(아키텍처 AD-8 상속).

- **역할 전환**은 상시 가능(Role Context Bar). 환자↔직원, 다른 환자 선택.
- **환자 신원 선택**은 목록에서 이름 고르기이며, 화면에 **"데모라 누구나 선택 가능, 진짜 보안 아님"** 을 명시(숨기지 않음).
- 환자 화면은 선택된 `patient_id`로만 데이터를 부른다(AD-8, API 필터). UI는 이걸 "본인 것만 보임"으로 보여주되 기밀 보장으로 과장하지 않는다.

## Key Flows

### Flow 1 — 이수민이 예약을 잡는다 (환자, 저녁, 폰)
1. 앱 진입 → 역할 선택에서 **환자**.
2. 환자 목록에서 **이수민** 선택(데모 고지 배너 보임). 환자 홈: "이수민님, 안녕하세요" + 내 예약(없으면 빈 상태).
3. "예약 잡기" → **진료과**(이비인후과) → **담당 의사**(김민재) → 날짜 → **슬롯 피커**에서 10:30 선택(예약된 슬롯은 흐림).
4. "예약하기" → 서버 가용성 재검증 통과.
5. **Climax:** "예약이 확정되었어요" toast, 환자 홈으로 돌아오면 방금 예약이 **대기** 배지로 목록 맨 위에 떠 있다. 전화 한 통 없이 끝. *(실패: 그새 슬롯이 찼으면 red 안내 + 슬롯 피커에서 그 칸이 taken으로 갱신 → 다른 슬롯 선택.)*

### Flow 2 — 박서준이 맞이하고 김민재가 기록한다 (직원, 데스크톱)
1. 역할 선택에서 **직원** → 직원 홈(오늘 예약 요약).
2. 처음 온 환자면 **환자 등록**(이름 필수 등) → 목록에 추가.
3. **예약 관리**에서 이수민의 **대기** 예약을 **확정**(담당 의사 김민재 확인, 필요 시 변경—가용성 재검사).
4. 진료 후, 그 **확정** 예약 행에서 **진료 기록 작성** → 진단·소견 + **처방 행** 2개 추가 → 저장.
5. **Climax:** 저장 순간 그 예약 배지가 **확정 → 완료**로 바뀐다(같은 트랜잭션의 부작용, AD-5). 종이 장부 없이 한 화면에서 등록→예약→기록→완료가 돌았다.

### Flow 3 — walk-in 환자 접수 `(P1)` (박서준, 데스크톱) *(2026-07-28 correct-course로 개정)*
1. 예약 없이 온 환자 → 미등록이면 **환자 등록** 먼저 → **예약 관리**에서 **대리 예약**.
2. 환자 검색·선택 → **진료과** 선택 → 담당 의사 **"자동 배정"** → **"가장 빠른 시간"** 한 번.
3. **Climax(정상):** 접수 완료 — 성공 toast가 **배정된 의사 이름**을 알려주고, 그 (의사, 슬롯)이 점유되어 같은 슬롯 예약을 막는다. 이후는 기존 환자와 동일한 흐름(확정 → 진료 기록 작성 → 완료).
4. **Climax(거부):** 그 시간에 그 과 의사가 전원 차 있으면 **red 인라인** "이 시간엔 모든 의사의 예약이 차 있어요. 다른 시간을 골라 주세요." + 그 셀 taken 갱신 → 다른 시간 선택(대기열 없음).

> 개정 사유(정직): 전용 walk-in 화면(예약 없이 즉시 기록) 대신 대리 예약 폼이 흡수한다 — 환자 등록·대리 예약이 이미 있어 전용 경로가 중복이기 때문. **한계:** 접수는 지금 진행 중인 슬롯이 아니라 **다음 빈 슬롯**으로 잡힌다(최대 30분 차). 상세: `sprint-change-proposal-2026-07-28.md`. 이에 따라 State Patterns 의 "walk-in 빈 의사 없음 → red **Dialog**"는 **red 인라인**(슬롯 충돌과 동일 처리)으로 수렴한다.
