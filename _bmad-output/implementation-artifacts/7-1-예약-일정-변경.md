# Story 7.1: 예약 일정 변경 (담당 의사 + 진료 시각)

## Story

As a 접수 직원,
I want 대기·확정 예약의 담당 의사와 진료 시각을 한 번에 바꾸기를,
so that 취소 후 재예약 없이 일정을 조정하고 그 환자의 예약 이력이 끊기지 않는다.

## Acceptance Criteria

**AC1 — 일정 변경 성립**
**Given** 대기 또는 확정 상태의 예약이 있을 때
**When** 직원이 `[변경]`에서 담당 의사·날짜·시각을 골라 저장한다
**Then** `PATCH /appointments/{id}/reschedule`로 `doctor_id`·`reserved_at`이 **한 SQL 문에서** 갱신되고 응답이 기존 `AppointmentOut` 정규 모델로 온다 (FR-19, AD-10)
**And** `status`·`hospital_department_id`는 어떤 경로에서도 바뀌지 않는다 (AD-5)

**AC2 — 부분 변경과 무변경**
**Given** 변경 요청에서
**When** 의사만 / 시각만 / 둘 다 바꿔 제출한다
**Then** 세 경우 모두 성립한다(미지정 필드는 현재 값 유지)
**And** 의사·시각이 둘 다 현재 값과 같으면 400 한국어로 거부한다
**And** 기존 `"이미 담당하고 있는 의사예요"` 400 규칙은 **제거**된다 — 의사를 그대로 두고 시각만 바꾸는 것이 정당한 요청이 됐다

**AC3 — 변경 불가 상태**
**Given** 완료 또는 취소 상태의 예약일 때
**When** 변경을 시도한다
**Then** 400 한국어로 거부한다(2.3 상태별 문구 **바이트 그대로** 계승)
**And** 검증과 UPDATE 사이 status 경합은 CAS 가드가 막고 409 한국어(기존 `CAS_CONFLICT_DETAIL`)로 안내한다

**AC4 — 의사 축 가용성 재검사**
**Given** 새 (의사, 슬롯)이 이미 점유돼 있을 때
**When** 저장한다
**Then** 409 한국어로 거부하고 슬롯 피커의 그 셀을 `taken`으로 갱신한다 (FR-15, AD-4, UX-DR3, UX-DR7)
**And** **자기 행을 제외**한다(`exclude_appointment_id`) — 자기가 점유한 슬롯으로의 "변경"이 자기 자신과 충돌하지 않는다

**AC5 — 환자 축 중복 차단**
**Given** 그 환자가 새 슬롯에 이미 **다른** 활성(대기·확정) 예약을 갖고 있을 때
**When** 저장한다
**Then** `db/migrations/006` 부분 유니크 인덱스가 UPDATE 를 거부하고, 기존 `_reject_unique_violation`(제약 이름 확인)이 409 환자 축 문구로 매핑한다 (FR-15b)
**And** 매핑 코드를 새로 만들지 않는다 — 생성 경로와 **같은 함수**를 쓴다

**AC6 — 과거 시각 가드**
**Given** 새 시각이 이미 지난 슬롯일 때
**When** 저장한다
**Then** 400 한국어로 거부한다(생성 경로 `create_appointment`와 **바이트 동일 문구**: `"이미 지난 시간이에요. 다른 시간을 골라 주세요."`)
**And** 이 가드는 `reserved_at`이 **실제로 바뀔 때만** 적용해, 과거 예약의 의사만 바꾸던 기존 동작을 깨지 않는다 (2.3 회귀 방지 — 기존 테스트가 이 계약을 고정)

**AC7 — 자기 예약을 taken 에서 제외**
**Given** `[변경]` 다이얼로그의 슬롯 격자가
**When** 렌더된다
**Then** **그 예약 자신이 점유한 슬롯은 `taken`으로 표시되지 않는다** — `GET /availability`가 `exclude_appointment_id`를 받아 **의사 축·환자 축 둘 다**에서 자기 행을 뺀다 (UX-DR3)
**And** 파라미터 미지정 시 응답이 기존과 바이트 동일해 기존 호출자(환자 예약·대리 예약)가 무수정으로 동작한다

**AC8 — 행 액션 통합**
**Given** 직원 예약 관리 목록에서
**When** 행 액션이 렌더된다
**Then** `[의사 변경]`이 `[변경]`으로 대체되고 버튼 수는 그대로다(대기 3개·확정 3개)
**And** 390×844에서 카드 오버플로 0, 콘솔 오류 0 (UX-DR11)
**And** `[변경]`은 비파괴적 `Dialog` 다 — 취소만 `AlertDialog` 를 유지한다 (UX-DR6 무변경)

**AC9 — `/doctor` 폐기 완결**
**Given** `PATCH /appointments/{id}/doctor` 폐기 후
**When** 레포를 검색한다
**Then** 라우터·서비스·db SQL·스키마·`lib/api.ts` 함수·해당 계약 테스트가 **함께** 제거되고 살아있는 코드·규칙 파일에 남은 참조가 0이다
**And** 완료 스토리 파일(2-3 등)의 언급은 시점 기록물이라 **그대로 둔다**

## Dev Notes

### 🎯 이 스토리의 한 줄 요약

**기존 의사 변경 UPDATE 경로를 `(doctor_id, reserved_at)` 두 컬럼으로 일반화하고, 프런트 다이얼로그에 날짜·슬롯을 얹는다.** 신규 게이트·신규 인덱스·신규 마이그레이션은 **하나도 없다**.

### 왜 이 스토리가 필요한가 (읽고 시작할 것)

2.3이 만든 `/doctor` 경로는 `doctor_id`만 만지고 `reserved_at`은 **명시적으로 동결**했다(`_UPDATE_APPOINTMENT_DOCTOR` 주석: *"status·reserved_at·hospital_department_id 는 건드리지 않는다"*). 그래서 **예약 생성 후 시각을 바꿀 경로가 앱 전체에 0개**다 — 직원은 취소 후 재예약밖에 못 해서 예약 행이 끊기고(새 id) 취소 행이 쌓인다. FR-19는 그 구멍을 닫는다.

### 백엔드 배선 청사진

**`_UPDATE_APPOINTMENT_SCHEDULE` — 한 문장 안 3층 가드**

```
① CAS      status = any(%(allowed_sources)s)        0행 → None → 409 (CAS_CONFLICT_DETAIL)
② 의사 축   not slot_taken(새 의사, 새 슬롯,          SlotTakenError → 409 슬롯 문구
             exclude_appointment_id = 자기 id)
③ 환자 축   006 인덱스가 UPDATE 시 자동 발동          UniqueViolation → _reject_unique_violation → 409
```

2.3 문에서 바뀌는 곳은 **두 줄뿐**이다:
- `set doctor_id = %(doctor_id)s` → `set doctor_id = %(doctor_id)s, reserved_at = %(reserved_at)s`
- `slot_taken_sql("(select reserved_at from target)")` → `slot_taken_sql("%(reserved_at)s")`

⚠️ 두 번째가 **핵심**이다. 2.3은 슬롯을 대상 행에서 유도했다(시각이 안 바뀌니까). 7.1은 **요청된 새 시각**으로 판정해야 한다 — 안 바꾸면 새 시각의 충돌을 검사하지 않고 옛 시각만 본다.
⚠️ `target` CTE 는 **삭제하지 말 것** — `cas_ok` 플래그가 `_interpret_*_row` 의 "CAS 우선" 규칙에 쓰인다.

**서비스 유효값 합성** — SQL 분기를 만들지 않기 위해 서비스가 먼저 합성한다:
```python
effective_doctor_id = payload.doctor_id if payload.doctor_id is not None else current["doctor_id"]
effective_slot = to_slot(payload.reserved_at if payload.reserved_at is not None else current["reserved_at"])
```
UPDATE 는 항상 두 컬럼을 쓴다(같은 값을 다시 써도 무해).

⚠️ **`to_slot()` 을 반드시 통과시킬 것** — 원시 payload 를 그대로 쓰면 003 의 `reserved_at` 30분 CHECK 를 위반해 원시 DB 에러가 난다(2.1이 겪은 함정). 이미 정렬된 값을 다시 floor 하는 건 무해한 no-op 이고, 저장 형태에 의존하지 않는 게 AD-3 규칙이다.

**무변경 판정(AC2)** — 비교는 **정규화 후**에 한다. 원시 payload 와 DB 값을 직접 비교하면 tz 표기·마이크로초 차이로 "안 바뀌었는데 바뀐 것"이 된다:
```python
unchanged = (effective_doctor_id == current["doctor_id"]
             and effective_slot == to_slot(current["reserved_at"]))
```
거부 문구(UX-DR10 — 정직·실행 가능, 직원 톤): `"바뀐 내용이 없어요. 담당 의사나 진료 시간을 바꿔 주세요."`

### 함정 5건 (실측 기반 — 여기서 넘어진다)

1. **과거 가드를 무조건 걸면 2.3 회귀** — `test_change_doctor_past_appointment_still_allowed` 가 "과거 예약의 의사 변경은 허용"을 고정하고 있다. 가드는 **`payload.reserved_at is not None` 일 때만** 적용한다.
2. **`/availability` 환자 축엔 제외 조건이 아예 없다** — `_SELECT_PATIENT_TAKEN_SLOTS` 를 보면 `exclude_appointment_id` 파라미터 자체가 없다. 의사 축(`occupied_sources_sql`)만 고치면 **자기 슬롯이 여전히 patient_taken 으로 와서** 화면이 막힌다. 두 쿼리 **모두** 고칠 것.
3. **의사 Select 의 "현재 의사 제외" 필터를 지워야 한다** — 현재 `doctorCandidates` 가 `d.id !== doctorTarget.doctor_id` 로 거른다. 그대로 두면 "의사 유지 + 시각만 변경"이 UI 에서 불가능하다(AC2 위반).
4. **`extra="forbid"` 는 유지하되 필수는 풀린다** — `doctor_id` 가 optional 이 되므로 `test_change_doctor_missing_doctor_id_returns_422` 의 계약이 바뀐다(422 → 이제 `reserved_at` 도 없으면 **서비스 400**). 테스트를 지우지 말고 **의도를 바꿔 재작성**한다.
5. **`slot-picker` 는 `takenMs` 미지정 시 루트 구조가 달라진다** — 범례가 없는 2상태 렌더다. 변경 다이얼로그는 항상 `takenMs`(=`unavailableMs`)를 넘겨 3상태 + 범례로 쓴다.
6. **409 셀 마킹은 의사 축(`takenMs`)에 넣는다 — 축을 가리려 들지 말 것.** 어느 축에서 온 409든 렌더는 `unavailableMs = takenMs ∪ patientBusyMs` 합집합을 쓰므로 결과가 같고, 이어지는 재조회가 두 축을 서버 진실로 덮는다. `chore/patient-slot-guard` 코드리뷰에서 환자 축 마킹으로 바꿨다가 **되돌린 이력**이 있다(응답이 두 축을 함께 주므로 무한 재시도가 애초에 안 생긴다). 같은 판단을 다시 하지 말 것.

### 테스트 전략 · 한계 (정직)

계약 테스트는 **db 계층을 monkeypatch** 한다 — 실 SQL·실 CTE·실 006 인덱스를 실행하지 않는다. 즉 `_UPDATE_APPOINTMENT_SCHEDULE` 의 `reserved_at` 반영, 자기 행 제외, 인덱스 발동은 **pytest 로 증명되지 않는다.** 실 보증은 아래 curl 실증과 브라우저 실측이 담당한다(`.claude/rules/workflow.md`).

### curl 실증 시나리오 (로컬 uvicorn + 실 Supabase, 6종)

1. **시각만 변경** — 대기 예약의 `reserved_at` 만 미래 빈 슬롯으로 → 200, `doctor_id` 불변, `status` 불변
2. **의사만 변경** — `doctor_id` 만 → 200, `reserved_at` 불변 (2.3 회귀 없음)
3. **둘 다 변경** — 200, 두 필드 모두 반영
4. **의사 축 409** — 다른 예약이 점유한 (의사, 슬롯)으로 → 409 `"이 시간엔 선택한 의사의 예약이 이미 있어요…"`
5. **환자 축 409** — 그 환자가 이미 잡은 다른 슬롯으로 → 409 `"이 환자는 그 시간에 이미 다른 예약이 있어요…"` (**006 인덱스가 UPDATE 에서 발동함을 증명**)
6. **자기 슬롯 유지** — `reserved_at` 을 **현재 값 그대로** + 의사만 변경 → 200(자기 행 제외 증명 — 제외가 없으면 여기서 409 가 난다)

추가: `GET /availability?…&exclude_appointment_id=<id>` 가 그 예약의 슬롯을 `taken`·`patient_taken` **양쪽에서** 빼는지 확인.

### 브라우저 실측 체크리스트 (390×844, Epic 6 회고 액션 #1)

- [ ] 대기·확정 행에 `[변경]` 1개(버튼 3개 유지), 완료·취소 행은 불변
- [ ] 다이얼로그 기본값 = 현재 의사·현재 날짜·현재 시각(선택됨 상태)
- [ ] **현재 슬롯이 `예약됨`으로 안 보인다**(AC7 — 이게 자기 행 제외의 눈으로 보는 증거)
- [ ] **시간 경과**: `page.clock` 으로 2시간 전진 후 열기 → 지난 슬롯이 목록에서 빠짐
- [ ] **같은 값 재선택**: 같은 날짜·같은 의사 다시 고르기 → 선택·가용성이 이유 없이 초기화되지 않음
- [ ] 다른 예약이 점유한 슬롯 = `예약됨`(비활성), 클릭 불가
- [ ] 409 → red 인라인 + 그 셀 즉시 `예약됨` + 다이얼로그 유지(입력 보존)
- [ ] 콘솔 0 · 가로 오버플로 0

### 검증 데이터 원복 규율

이 스토리는 **예약을 새로 만들지 않고 기존 행을 옮긴다** — 원복은 삭제가 아니라 **원래 `doctor_id`·`reserved_at` 로 되돌리는 UPDATE** 다. 실증 전에 대상 행의 원값을 반드시 적어 둘 것.
충돌 시나리오(4·5)를 위해 예약을 새로 만들었다면 처방 → 기록 → 예약 순으로 삭제(공용 라이브 DB — 시드 재실행 절대 금지).
