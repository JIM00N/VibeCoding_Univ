# Story 2.4: 예약 목록 진료과별·담당의사별 색상 구분

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 접수 직원,
I want 예약 목록에서 진료과와 담당 의사를 색으로 한눈에 구분하기를,
so that 여러 예약을 과·의사별로 빠르게 훑고 헷갈림 없이 관리한다.

> 출처: Story 2.2 코드리뷰 중 사용자가 발견한 개선점 #3(진료과 구분)·#5(의사 이름 배경색). epics.md에 없던 신규 UX 스토리(표시 전용). 로직/충돌검사/취소되돌리기/의사변경과 무관.

## Acceptance Criteria

**AC1 — 담당 의사 색 배지 (#5, UX-DR9)**
**Given** 직원 예약 관리 화면(`/staff/appointments`)의 예약 목록에서
**When** 각 행의 담당 의사가 표시된다
**Then** 의사 이름이 그 의사에 **결정적으로 매핑된 부드러운 배경색 배지(칩)** 안에 표시된다 — **글자색이 아니라 이름을 둘러싼 작은 배경색**(사용자 요청 문구). 같은 의사는 항상 같은 색.
**And** 색만이 아니라 **의사 이름 텍스트를 항상 병기**한다(색맹·스크린리더 — UX-DR9).
**And** 담당 의사가 없으면(`doctor_name` null) 배지 없이 기존처럼 "—"로 표시한다.

**AC2 — 진료과 색 구분 (#3)**
**Given** 예약 목록에서
**When** 각 예약의 진료과가 표시된다
**Then** 진료과가 그 진료과에 결정적으로 매핑된 부드러운 배경색 배지로 구분되고, 같은 진료과는 항상 같은 색이다.
**And** 진료과 이름 텍스트를 항상 병기한다.

**AC3 — 별도 카테고리 팔레트: 상태색·primary와 절대 충돌 금지 (DESIGN.md)**
**Given** 진료과·의사에 새로 도입하는 색은
**When** 팔레트를 고를 때
**Then** **상태 4색(대기 amber·확정 blue·완료 green·취소 gray)과 primary emerald(`#047857`)를 재사용하지 않는** 별도의 카테고리 팔레트를 쓴다 — 상태 시맨틱(데이터 계약)을 흐리지 않기 위해(DESIGN.md: "상태 4색은 상태에만").
**And** 초록/emerald 계열을 피해 green-adjacency 규칙을 지키고, gray 계열도 피한다(취소색과 혼동 방지).
**And** 색은 **연한 배경 + 진한 텍스트**(상태 배지와 같은 밀도·톤)로 "차분한 임상" 정체성을 지킨다 — 채도 높은 요란한 색·그라디언트 금지(시각 소음 최소화, DESIGN.md).

**AC4 — 결정적·안정적 매핑, 확장 안전**
**Given** 진료과/의사 id로 색을 고를 때
**When** 매핑한다
**Then** **id 기반 결정적 매핑**(같은 id = 같은 색, 재조회·리렌더에도 불변)이다 — 랜덤/비결정 매핑 금지.
**And** 팔레트보다 많은 진료과/의사가 생겨도 안전하게 순환(색은 재사용되되 이름 텍스트로 최종 구분).
**And** 시드 범위(진료과 3·의사 6)에서 인접 항목이 가급적 서로 다른 색을 받는다.

**AC5 — 표시 전용, 2.2 회귀 0**
**Given** 이 스토리는
**When** 구현된다
**Then** **표시(UI)만** 바꾼다 — 예약 상태 전이·API·DB·기존 상태 배지 로직을 건드리지 않는다(add-only).
**And** 데스크톱 표(`≥md`)와 모바일 카드(`<md`) 둘 다 반영되고, 로딩/빈/오류 상태와 확정·취소 액션은 그대로 동작한다(2.2 회귀 0).
**And** `npm run lint` 클린 + `npm run build` 성공.

### 🎨 팔레트 설계 지침 (DESIGN.md 준수)

- **피해야 할 색(충돌):** amber(대기)·blue(확정)·green/emerald(완료·primary)·gray/slate(취소). 이 계열은 상태 시맨틱과 혼동된다.
- **쓸 수 있는 계열(예):** rose/red-lite(단 destructive red와 구분되게 연하게)·orange·violet/purple·indigo(확정 blue와 명도 차 확보)·cyan(확정 blue와 채도/명도 차)·pink·fuchsia·teal(emerald와 명도 차 확보 시). 각 **연한 bg + 진한 fg**(상태 배지처럼 `bg-[#…] text-[#…]`).
- **톤:** 차분한 임상 — 파스텔/저채도. 요란한 원색·형광 금지. 상태 배지와 같은 시각 밀도.
- **결정적 매핑:** `(id - 1) % PALETTE.length`. 시드 id 고정이라 안정. 팔레트 8~10색이면 의사 6·진료과 3에 충분(순환 전).
- **한 행 과·의사 색 충돌:** 같은 팔레트를 두 열이 공유하면 우연히 같은 색이 나올 수 있음 — 의사에 index 오프셋을 주거나(예: `+3`), 팔레트가 넉넉하면 무시 가능(텍스트로 구분되므로 치명적 아님). dev 판단.

### 핵심 안티패턴 (하지 말 것)

- ❌ **상태 4색·primary emerald를 진료과/의사 색으로 재사용** — 상태 시맨틱이 흐려진다(DESIGN.md 최우선 규칙).
- ❌ **색만으로 구분**(이름 텍스트 생략) — UX-DR9 위반(색맹·SR).
- ❌ **랜덤/비결정 색**(리렌더·재조회마다 색이 바뀜) — id 기반 결정적이어야 함.
- ❌ **채도 높은 요란한 색·그라디언트** — "차분한 임상" 톤·시각 소음 최소 위반.
- ❌ **로직/상태/API 변경** — 표시 전용. `status`·`doctor_id`를 바꾸지 말 것.
- ❌ **하드닝/재사용 파일 개변** — `appointment-status.ts`·`appointment-status-badge.tsx`(그대로 재사용), `lib/api.ts`의 `request`, 백엔드 전부. add-only.
- ❌ **`RoleContextBar`·기타 공유 컴포넌트 시그니처 변경**.
