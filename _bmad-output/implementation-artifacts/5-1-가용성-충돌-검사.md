## Story

As a 시스템(직원/환자 대신 무결성을 지키는),
I want 예약 생성과 의사 배정/변경 시 (의사, 슬롯) 충돌을 앱이 차단하기를,
so that 한 의사가 같은 슬롯에 이중 배정되지 않는다.

**한 줄 성격:** **백엔드 중심 + 프런트 2화면.** 서버의 점유 쓰기는 실제로 **2곳뿐** — `POST /appointments`(환자 예약·직원 대리 예약이 **같은 엔드포인트**를 쓴다 — Epic 6 회고의 "4번째 진입점"은 서버에선 자동 커버)와 `PATCH /appointments/{id}/doctor`(재배정). 취소는 별도 해제 로직이 필요 없고(충돌 쿼리가 status로 자연 해제), walk-in은 미구현(5.3)이라 충돌원 union만 미리 본다. 만드는 것: ① 충돌 조각 SQL 1벌(`app/db/availability.py`) + 두 쓰기 문에 CTE 내장, ② taken 사전 표시용 `GET /availability`, ③ 과거 시각 서버 가드, ④ 프런트 taken 3상태(slot-picker 확장 + 2화면 배선). **신규 마이그레이션 0**(30분 CHECK는 003이 이미 담당, `(doctor,slot)` DB 유니크는 두 테이블 합집합이라 불가능 — 설계 결론).

## Acceptance Criteria

**AC1 — 슬롯 정규화 식은 한 벌 (AD-3)**
**Given** 슬롯 키를 계산할 때
**When** Python `to_slot()`(기존 `app/slots.py`, 무수정)과 SQL floor 식이 실행된다
**Then** 둘이 동일하게 30분 격자(UTC floor)로 계산한다. SQL floor 식은 `app/db/availability.py`의 **상수 1벌**로만 존재하고(`date_bin` 권장 — 세션 tz 불변), 점유 판정의 source of truth는 SQL 충돌 쿼리다. `medical_record.visited_at`은 30분 CHECK가 없으므로 **반드시 SQL에서 floor**해 비교한다(원시 timestamp 비교 금지)

**AC2 — 단일 관문·원자성 (AD-4, Epic 2 회고 액션 #4 방식)**
**Given** 점유가 발생하는 쓰기(예약 생성 = 환자·대리 공용 `POST /appointments` · 의사 변경 `PATCH /appointments/{id}/doctor`)일 때
**When** 삽입/갱신한다
**Then** 충돌 검사와 쓰기를 **단일 CTE 문 하나**(= 한 커넥션 = 한 트랜잭션)로 수행한다. 충돌 조각(union + floor)은 `app/db/availability.py`에 **정확히 한 벌**만 정의하고 두 쓰기 문과 조회가 조합해 쓴다 — `check_and_occupy(conn,…)` 함수 분리 대신 이 프로젝트의 확립 관용구를 따른다(Dev Notes "구현 결정" 참조)

**AC3 — 충돌원은 합집합 (AD-4)**
**Given** 후보 (의사, 슬롯)을 볼 때
**When** 충돌을 검사한다
**Then** `appointment`(status ∈ 대기·확정) ∪ walk-in `medical_record`(`appointment_id` is null)을 합집합으로 보고, **취소=해제**(status 필터로 자연 해제, 별도 로직 0)·**완료=무관**으로 제외한다. walk-in 행은 5.3 전이라 실 코드 경로가 없지만 **curl 실증에서 수동 SQL 행으로 union 동작을 증명**한다

**AC4 — 충돌 거부: 409 + 두 화면 taken 갱신 (FR-15, UX-DR3, UX-DR7, UX-DR10)**
**Given** 이미 점유된 (의사, 슬롯)일 때
**When** 예약 생성을 시도한다
**Then** **409** `{"detail": "이 시간엔 이미 예약이 있어요. 다른 시간을 골라 주세요."}`로 막고(INSERT 0행 — 과거 예약처럼 조용히 쌓이지 않는다), **두 화면 모두**(`app/patient/book` · `proxy-booking-dialog`)에서 red 인라인(`role="alert"`, 서버 detail 그대로)을 보여주며, 그 셀을 즉시 `taken`(비활성)으로 갱신하고 선택을 해제한 뒤 가용성을 재조회한다. 폼 입력(진료과·의사·날짜)은 보존된다

**AC5 — taken 사전 표시: `GET /availability` + 슬롯 피커 3상태 (UX-DR3, UX-DR9, AD-10)**
**Given** 두 화면에서 (의사, 날짜)를 골랐을 때
**When** 슬롯 격자를 그린다
**Then** 신규 `GET /availability?doctor_id=&start=&end=`(ISO-8601 UTC 범위)가 돌려준 점유 슬롯 목록(`{"doctor_id": …, "taken": [슬롯 ISO…]}`)으로 해당 셀을 `taken`으로 렌더한다 — muted + disabled + 셀 안 "예약됨" 텍스트(색만으로 구분 금지) + SR 라벨 "…, 예약됨" + 키보드 roving에서 제외 + 범례(예약 가능/선택됨/예약됨). taken 미지정 시 기존 2상태 렌더와 **동일**(회귀 0). 그 날짜 슬롯이 전부 taken이면 "이 날짜는 예약이 모두 찼어요. 다른 날짜를 골라 주세요." 안내. 가용성 조회 실패는 치명 아님 — taken 없이 렌더(제출 409가 최종 방어)

**AC6 — 의사 변경 재검사 (FR-7, AD-4)**
**Given** 의사 변경(재배정)일 때
**When** 새 (의사, 슬롯) 점유를 확인한다
**Then** **자기 행을 제외**(`exclude_appointment_id`)하고 검사하며, 충돌이면 **409** `{"detail": "이 시간엔 선택한 의사의 예약이 이미 있어요. 다른 의사를 선택해 주세요."}` — 기존 CAS 409("예약 상태가 방금 바뀌었어요…")와 **구분**된다. 이전 슬롯 해제 + 새 슬롯 점유는 `doctor_id` 단일 UPDATE로 원자 성립(점유가 예약 행 자체에서 유도되므로 별도 해제 로직 0). 직원 의사 변경 다이얼로그 **UI 변경 0** — 기존 catch(toast + 목록 재동기화)가 새 409 문구를 그대로 표시한다

**AC7 — 과거 시각 서버 가드 (Epic 6 회고 액션 #6③: 가드 배치 정리)**
**Given** `reserved_at`이 이미 지난 시각일 때
**When** 예약 생성을 시도한다
**Then** 서버가 `to_slot(reserved_at) < now(UTC)`이면 **400** `{"detail": "이미 지난 시간이에요. 다른 시간을 골라 주세요."}`로 거부한다(6.3 High "지난 슬롯 예약 가능"의 **서버측 마감** — 지금은 프런트만 막는다). 환자 화면(`patient/book`)에도 6.3과 같은 **제출 직전 클라이언트 재검증**을 이식한다(현재 없음). 의사 변경은 `reserved_at`을 바꾸지 않으므로 과거 가드 없음. `reserved_at` 30분 정렬은 기존 003 CHECK가 보강(AD-9) — **신규 마이그레이션 0**

**AC8 — 회귀 0 · 품질 게이트**
**Given** 이 스토리가 백엔드 쓰기 경로와 동결 프런트 파일을 건드릴 때
**When** 구현한다
**Then** 기존 계약 유지: db 함수 반환 형태 불변(충돌은 `SlotTakenError` 예외 — 기존 테스트 픽스처 무수정), 기존 105 테스트 전체 그린 + 신규 계약 테스트, `npm run lint`·`npm run build` 그린, 실 Supabase **curl 실증**(충돌 409·취소 해제·walk-in union·과거 400·availability), **브라우저 실측 2화면**(390×844 + ≥md, 콘솔 0) — **"시간 경과"·"같은 값 재선택" 시나리오 필수**(Epic 6 회고 액션 #1), 검증 데이터 SQL 원복(기록→예약 순)

> 경계(정직): 앱 레벨 검사는 동시 요청이 없는 단일 세션 전제에서 차단을 보장하며, 동시 요청 경쟁(TOCTOU)의 완전 차단은 범위 밖이다(아키텍처 Deferred — EXCLUDE 제약/점유 테이블 단일화). 자동 배정(5.2)·walk-in 생성(5.3)도 범위 밖 — 이 스토리는 조각을 세우고 두 기존 쓰기 경로에만 건다.

## Dev Notes

### 🎯 이 스토리의 한 줄 요약

**충돌 판정 SQL 조각 1벌을 세우고, 이미 있는 두 쓰기 문에 CTE로 내장한다.** 서버 진입점은 `POST /appointments`(환자·대리 공용)와 `PATCH /appointments/{id}/doctor` 둘뿐이라 접촉면이 작다. 프런트는 slot-picker에 taken 3상태를 얹고 두 화면에 배선한다. 5.2(자동 배정)·5.3(walk-in)이 이 조각(`_OCCUPIED_SOURCES`·`_SLOT_TAKEN`·`select_taken_slots`)을 그대로 재사용한다 — 여기서 잘 세우면 다음 두 스토리는 소비자다.

### 구현 결정 — AD-4 `check_and_occupy(conn,…)` vs 이 프로젝트의 관용구

AD-4 원문은 "호출자 트랜잭션(`conn`)을 받는 단일 함수"를 요구하지만, **현 db 계층은 conn을 인자로 받는 함수가 0개**다(모든 함수가 `with get_pool().connection()`으로 자기 커넥션을 연다). 이 프로젝트가 같은 문제(검사+쓰기 원자성)에 이미 채택·검증한 해법은 **"단일 CTE 문 = 한 커넥션 = 한 트랜잭션"**(Epic 2 회고 액션 #4 → 3.1 기록+완료 전이 CTE, Epic 3 회고 "핵심 패턴이 복리로 작동"). "패턴이 아니라 이유를 복사" — AD-4의 이유(단일 관문·검사↔쓰기 원자·로직 발산 방지)는 다음으로 전부 성립한다:

- **단일 관문** = 충돌 조각 SQL이 `app/db/availability.py`에 정확히 한 벌, 모든 소비자가 조합만 한다.
- **원자성** = 검사와 쓰기가 같은 SQL 문 안(문장 원자성) — conn 전달보다 오히려 강하다.
- **발산 방지** = 5.2·5.3도 같은 조각을 조합(아키텍처 Deferred의 "같은 헬퍼 공유" 요구 충족).

conn 전달식으로 가려면 db 계층 커넥션 관용구 전면 개편이 필요하다 — 이 스토리에서 하지 말 것(회귀 위험 대비 이득 0).

### SQL 청사진 (`app/db/availability.py` — floor·union은 여기 한 벌뿐)

```python
# 슬롯 floor 식 — SQL 쪽 유일한 정의(AD-3). date_bin은 절대시간 연산이라 세션 TimeZone 무관
# (date_trunc('hour')는 세션 tz를 타서 비정시 오프셋에서 어긋난다). PG14+, Supabase OK.
_SLOT_EXPR = "date_bin('30 minutes', {col}, timestamptz '2000-01-01 00:00:00+00')"

# 충돌원 합집합(AD-4): 활성 예약 ∪ walk-in 기록. 취소·완료는 여기서 자연 제외된다.
# exclude 는 의사 변경의 자기 행 제외용 — 생성·조회는 None 을 넘긴다(조각은 한 벌 유지).
_OCCUPIED_SOURCES = """
    select a.reserved_at as occupied_at
    from public.appointment a
    where a.doctor_id = %(doctor_id)s
      and a.status in ('대기', '확정')
      and (%(exclude_appointment_id)s::bigint is null or a.id <> %(exclude_appointment_id)s)
    union all
    select m.visited_at
    from public.medical_record m
    where m.doctor_id = %(doctor_id)s
      and m.appointment_id is null
"""

_SLOT_TAKEN = f"""exists (
    select 1 from ({_OCCUPIED_SOURCES}) o
    where {_SLOT_EXPR.format(col="o.occupied_at")} = %(slot)s
)"""

class SlotTakenError(Exception):
    """(의사, 슬롯) 점유 충돌 — 서비스가 409 로 매핑한다."""
```

게이트 내장 INSERT(`db/appointments.py` `_INSERT_APPOINTMENT` 교체 형태):

```sql
with taken as (
    select {_SLOT_TAKEN} as slot_taken
),
inserted as (
    insert into public.appointment (patient_id, hospital_department_id, doctor_id, reserved_at, status)
    select %(patient_id)s, %(hospital_department_id)s, %(doctor_id)s, %(reserved_at)s, '대기'
    from taken where not slot_taken
    returning id, patient_id, hospital_department_id, doctor_id, reserved_at, status
)
select t.slot_taken, i.id, i.patient_id, i.hospital_department_id, i.doctor_id, i.reserved_at, i.status,
       p.name as patient_name, doc.name as doctor_name, d.name as department_name
from taken t
left join inserted i               on true
left join public.patient p         on p.id  = i.patient_id
left join public.hospital_department hd on hd.id = i.hospital_department_id
left join public.department d      on d.id  = hd.department_id
left join public.doctor doc        on doc.id = i.doctor_id
```

db 함수 처리: `row["slot_taken"]` true → `raise SlotTakenError` · `row["id"]` null → 기존 500 방어 경로 · 정상 → `slot_taken` 키 제거 후 반환. **반환 계약이 기존과 동일**해 기존 테스트 픽스처(`_fake_row`) 42개가 무수정으로 산다. FK 위반(없는 환자)은 지금처럼 driver 예외로 올라간다.

게이트 내장 의사 변경(`_UPDATE_APPOINTMENT_DOCTOR`): 같은 `taken` CTE(+`exclude_appointment_id`=자기 id) + `update … where id=%(id)s and status = any(%(sources)s) and not (select slot_taken from taken)`. 해석 순서: `slot_taken` → `SlotTakenError`(409 슬롯) / 0행 → `None`(기존 CAS 409) / 정상 → row. `slot` 파라미터는 서비스가 `to_slot(current["reserved_at"])`로 계산해 넘긴다 — 예약 시각 변경 기능이 없어 prefetch 값이 안전하다.

가용성 조회: `select distinct {_SLOT_EXPR(col='o.occupied_at')} as slot from ({_OCCUPIED_SOURCES}) o where o.occupied_at >= %(start)s and o.occupied_at < %(end)s order by slot` (exclude=None).

### 과거 시각 가드 — 3층 배치 정리 (Epic 6 회고 액션 #6③)

| 층 | 위치 | 역할 |
|---|---|---|
| 표시 | 두 화면의 `slots` 필터(기존) | 지난 슬롯을 애초에 안 보여줌 |
| 제출 직전 | 클라이언트 재검증 — 대리(기존 6.3) + **환자(이번에 이식)** | 오래 열어둔 폼의 UX 안내(인라인) |

서버 비교는 `slot < datetime.now(timezone.utc)` — 진행 중 슬롯(10:00 슬롯을 10:14에)도 거부해 프런트 필터(`slot iso > now`)와 일관된다. 충돌 검사(409)보다 **먼저** 걸어 과거+충돌 동시일 때 400이 이긴다(입력 자체 결함 우선).

### 409 vs 400 — 코드 선택 기준

- **409** = 다른 행이 점유(경합 성격) — 슬롯 충돌 2종. 기존 CAS 409 선례와 결. 프런트가 `ApiError.status === 409`로 "그 셀 taken 갱신" 분기를 태운다.
- **400** = 요청 자체 결함 — 과거 시각·의사 미선택·소속 불일치(기존 유지).
- 문구 정본은 **서버**(AD-10 `{"detail": …}`) — 프런트 인라인은 detail을 그대로 렌더한다. epics 원안 "이 시간엔 이미 예약이 있어요. 다른 시간을 골라 주세요."("골라 주세요" 띄어쓰기 — 횡단 규약 표기) 채택.

### taken 표시 설계 — slot-picker 확장 결정 (Epic 6 회고 액션 #6②)

`slot-picker.tsx`는 지금까지 동결이었다. **이 스토리에서 옵션 prop으로 확장한다** — 두 화면이 자동 공유되고, `takenMs` 미지정이면 렌더 경로가 기존과 완전 동일해 add-only 정신(기본 동작 불변)을 지킨다. 대안(각 화면에서 slots 배열을 가공해 별도 비활성 UI)은 taken 시각·SR·키보드 규칙이 2벌로 갈라져 기각.

- **매칭 키는 epoch ms** (`ReadonlySet<number>`): Pydantic 직렬화(`+00:00`)와 프런트 슬롯 iso(`Z`)가 문자열로는 어긋난다. `new Date(iso).getTime()` 정규화가 유일하게 안전.
- 시각 스펙(목업 `mockups/booking.html`): muted 배경 + 흐린 텍스트 + 시각 취소선("예약됨" 라벨엔 취소선 없음) + 셀 안 `<small>예약됨</small>` 2행. 색만으로 구분 금지(UX-DR9)는 셀 내 텍스트+범례가 담당.
- SR: `aria-label` "…, 예약됨"(기존 "예약 가능"/"선택됨"에 3번째 값). taken 셀은 `disabled`라 포커스 불가 → roving tabindex 진입 인덱스와 방향키 스킵 로직 수정 필수(`slot-picker.tsx:37-49`가 현재 무조건 `(index±1) % length` 이동 + 즉시 onChange — taken을 건너뛰고, 전부 taken이면 이동 안 함).

- **conn 전달식 `check_and_occupy` 함수·db 계층 커넥션 개편 금지** — 위 "구현 결정" 참조.
- **floor 식을 두 번째로 적지 말 것** — SQL은 `_SLOT_EXPR` 한 벌, Python은 기존 `to_slot()`(무수정). 쿼리마다 `date_trunc`/`extract`를 다시 쓰는 순간 AD-3 위반.
- **5.2·5.3을 미리 만들지 말 것** — 자동 배정(의사 비움 허용)·walk-in 생성·red Dialog 거부는 다음 스토리 소유. 이 스토리의 프런트 거부 UX는 **red 인라인**뿐(walk-in의 red Dialog와 다른 패턴 — UX-DR7).
- **booking-slots·formatReservedAt·orDash·ErrorState 중복을 여기서 통합하지 말 것** — 정리 스토리가 "5.1 완료 직후"로 못 박혀 있다(Epic 6 회고 액션 #5). 환자 화면을 여는 김에 정리하고 싶어도 참는다 — 이 스토리의 diff는 가용성만.
- **`POST /medical-records`(기록+완료 전이)에 점유 검사를 넣지 말 것** — 예약 기반 기록은 슬롯을 새로 점유하지 않는다(완료=과거, 기존 주석 그대로).
- **취소 경로에 "슬롯 해제" 코드를 넣지 말 것** — 충돌 쿼리의 status 필터가 해제 그 자체다.
- **`GET /appointments?doctor_id=`를 taken 데이터원으로 쓰지 말 것** — 상태·날짜 필터 없이 전체 반환 + walk-in 미포함 + 환자 화면에 타 환자 정보 과다 노출. 전용 `GET /availability`가 정답.
- **환자 화면의 신원 가드·안심 톤·성공 카드·데모 배너를 건드리지 말 것** — 이번 동결 해제는 가용성 배선·제출 재검증·동일값 early-return까지만.
- **문구를 프런트에 하드코딩해 서버와 2벌 만들지 말 것** — 충돌 인라인은 서버 detail 그대로.
