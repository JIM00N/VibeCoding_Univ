# Story 2.1: 환자 예약 생성 (진료과·30분 슬롯·담당 의사 직접 선택)

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 환자,
I want 진료과·시각(30분 슬롯)·담당 의사를 골라 예약을 만들기를,
so that 전화 한 통 없이 앱에서 진료 예약을 잡는다.

## Acceptance Criteria

**AC1 — 예약 생성: `POST /appointments` → `status=대기`, `doctor_id` 채워짐 (FR-6 P0, AD-5, AD-10)**
**Given** 환자 신원이 선택된 상태(Epic 1, `usePatientIdentity()`)에서
**When** 진료과를 고르고 30분 슬롯 피커에서 시각을 선택하고 담당 의사를 직접 선택해 제출한다
**Then** `POST /appointments`로 `status=대기`이고 `doctor_id`가 채워진 예약이 생성되고, 응답이 리소스 정규 모델(정수 FK id + 평평한 표시 필드)로 온다
**And** `doctor_id`가 항상 채워져 이후 진료 기록의 `doctor_id NOT NULL`까지 정합이 유지된다 (Epic 3 대비)
**And** 선택한 의사는 **선택한 진료과(`hospital_department_id`) 소속**이어야 한다(서비스가 검증 — DB FK는 소속 일치를 강제하지 않음, §백엔드 청사진 GOTCHA)

**AC2 — 30분 슬롯 피커: available/selected, 접근 가능한 이름, 키보드 (UX-DR3, UX-DR9)**
**Given** 예약 화면의 슬롯 피커가
**When** 렌더된다
**Then** 30분 격자 셀이 **available/selected** 두 상태로 표시되고(데스크톱 4열·모바일 3열), 각 셀에 한국어 접근 가능한 이름(예: `"10시 30분, 예약 가능"`/`"…, 선택됨"`)이 있으며, 키보드로 조작 가능하다(방향키 이동 + Space/Enter 선택, 포커스 링 항상 보임)

> ↪ **`taken`(예약됨·비활성) 셀과 슬롯 충돌 차단은 Epic 5(FR-15). 2.1에서는 만들지 않는다** — P0는 검사 없이 생성한다(§스코프 경계).

**AC3 — 담당 의사 미선택 시 인라인 안내 + 생성 차단 (FR-6 P0, UX-DR9)**
**Given** 담당 의사(또는 진료과·슬롯 등 필수값)를 선택하지 않았을 때
**When** 제출을 시도한다
**Then** 예약이 생성되지 않고, 서버 도달 전에 라벨된 인라인 안내(`"담당 의사를 선택해 주세요."` 등)로 막는다
**And** 방어적으로 서버에 도달하면 `4xx {"detail": "…한국어…"}`(문자열)를 반환한다 (AD-10)

**AC4 — `reserved_at`은 30분 경계만 저장 → DB CHECK 통과 (AD-3, AD-9)**
**Given** 예약 시각을 선택했을 때
**When** 저장한다
**Then** `reserved_at`은 30분 경계(분 ∈ {0,30}, 초 = 0)로 정규화되어 저장되어 `appointment_reserved_at_slot_check` CHECK를 통과한다 — 백엔드 서비스가 `slots.to_slot()`으로 floor한 값을 INSERT한다(원시 입력을 그대로 넣지 않음)

**AC5 — 성공 toast + 방금 만든 예약을 대기 배지로 확인 (UX-DR7, UX-DR2)**
**Given** 예약 생성에 성공했을 때
**When** 저장이 끝난다
**Then** 성공 toast를 띄우고, **방금 생성한 예약을 `POST` 응답 데이터로** 대기(amber) 상태 배지와 함께 확인 영역에 표시한다(진료과·의사·시각 요약)

> 📎 **AC5 완료 판정(스코프 경계):** "목록에 반영"은 **방금 만든 예약 한 건을 POST 응답으로 보여주는 것**으로 충족한다. 환자용 예약 **목록 조회**(`GET /appointments?patient_id=`)는 **Epic 4(Story 4.1)** 다. 이 스토리에서 그 엔드포인트를 **부르지도 만들지도 말 것** — 없어서 404/에러만 난다(§스코프 경계, [[feedback-verify-browser-render]]와 1.5 안티패턴 동일 규율).

## Dev Notes

### 🎯 이 스토리의 한 줄 요약

`patients` 리소스를 **`appointments`로 통째 복제**하고 refdata에 **`GET /doctors`** 한 개를 더한 뒤, `usePatientIdentity().patient.id`와 `slots.to_slot()`을 물려 **충돌 검사 없이(P0)** `POST /appointments`를 치는 **환자 예약 화면(30분 슬롯 피커 = 이 앱 첫 커스텀 컴포넌트)** 을 만든다.

### 이 스토리가 딛고 서는 뼈대 — 이미 준비된 것 (재사용, 재발명 금지)

Epic 1 회고의 1번 성공 요인이 "**계층 규약(AD-2)의 매끄러운 복제** — 1.1의 refdata 3계층을 1.3·1.4가 거의 복사로 확장"이다. 2.1도 같은 방식으로 `patients`를 복제한다.

### 백엔드 청사진 — SQL·스키마 (실측 기반)

> ⚠️ **스키마 실측 주의:** 기본 9테이블 `CREATE TABLE`은 레포에 없고 Supabase(`fphsxoweprztrekckzui`)에 실배포돼 있다. 아래 컬럼명은 `db/seed/004_seed.sql`의 INSERT 컬럼과 `db/refdata.py`·`db/patients.py` SQL로 삼각검증한 것 — INSERT 컬럼 목록 확정 전 **라이브 DB에서 `appointment` 컬럼명(특히 `patient_id`, `reason` 유무, `status` 기본/CHECK)을 한 번 확인**할 것.

**`appointment` 관련 컬럼(재구성):** `id`(bigint IDENTITY, PK, **INSERT 금지**), `patient_id`(FK→patient, NOT NULL), **`hospital_department_id`**(FK→hospital_department, NOT NULL — `department_id` 아님, 이 이름이 가장 load-bearing), `doctor_id`(FK→doctor, **nullable**이나 P0가 채움), `reserved_at`(timestamptz, NOT NULL), `status`(text, CHECK ∈ 대기·확정·완료·취소, **기본 `대기`**).

**reserved_at CHECK(`003_reserved_at_check.sql`, 제약명 `appointment_reserved_at_slot_check`):**
```sql
check ( extract(minute from reserved_at) in (0, 30) and extract(second from reserved_at) = 0 )
```
`10:17` 같은 값은 거부(원시 DB 에러) → **서비스가 `to_slot()`으로 floor한 값을 넣는다.**

**`POST /appointments` INSERT (한 왕복 CTE — 표시 필드 조인):**
```sql
with inserted as (
    insert into public.appointment (patient_id, hospital_department_id, doctor_id, reserved_at, status)
    values (%s, %s, %s, %s, '대기')
    returning id, patient_id, hospital_department_id, doctor_id, reserved_at, status
)
select a.id, a.patient_id, a.hospital_department_id, a.doctor_id, a.reserved_at, a.status,
       p.name  as patient_name,
       doc.name as doctor_name,
       d.name  as department_name
from inserted a
join public.patient p              on p.id  = a.patient_id
join public.hospital_department hd on hd.id = a.hospital_department_id
join public.department d           on d.id  = hd.department_id
left join public.doctor doc        on doc.id = a.doctor_id
```
`doctor`는 `LEFT JOIN`(스키마 nullable 정직). `status`는 명시적 `'대기'`(AC·기본값과 일치, 자기문서화).

**`GET /doctors` SQL(진료과별 의사):**
```sql
select doc.id as id, doc.name as name,
       doc.hospital_department_id as hospital_department_id,
       d.name as department_name
from public.doctor doc
join public.hospital_department hd on hd.id = doc.hospital_department_id
join public.department d on d.id = hd.department_id
where doc.hospital_department_id = %s   -- 필터 없으면 이 줄 생략(전체)
order by doc.name, doc.id
```

**GOTCHA(반드시 처리):**
- **의사↔진료과 정합은 DB가 강제하지 않는다.** `appointment.doctor_id` FK는 의사 존재만 보장하고 `doctor.hospital_department_id == appointment.hospital_department_id`는 확인하지 않는다 → 서비스가 검증하지 않으면 김민수(내과)를 이비인후과 슬롯에 예약할 수 있다. **서비스에서 선택 의사가 선택 진료과 소속인지 검사**(아니면 400 한국어).
- **도메인 거부는 `HTTPException(400, detail="한국어 str")`.** `detail`이 리스트/객체(422)면 `lib/api.ts`가 일반 메시지로 대체하므로, 친절한 문구는 반드시 **문자열 400**으로.
- **RLS는 9테이블 ON(deny-by-default).** 백엔드는 `DATABASE_URL`로 테이블 소유자 접속 → RLS 우회. 모든 예약 I/O는 풀(`db/pool.py`) 경유 서버측. 브라우저 anon 키로는 아무것도 못 읽음.

### 슬롯 피커 설계 (첫 커스텀 컴포넌트 — AC2, AC4)

- **ARIA = radiogroup**(단일 선택 격자). 컨테이너 `role="radiogroup"` + `aria-label`; 셀 `role="radio"` + `aria-checked`. WAI-ARIA APG Radio 패턴: **roving tabindex**(선택/첫 셀만 `tabIndex=0`), 방향키로 포커스+선택 이동(양끝 wrap), Space/Enter 선택. shadcn `<Button>`이 아니라 **plain `<button type="button">`** 사용(토글 변형 없음; select/page.tsx의 `focus-visible:ring-3 ring-ring/50` 셀 선례).
- **상태 2개(P0):** available = outline/`bg-card` 클릭 가능; selected = `bg-primary text-primary-foreground`(emerald, 하드코딩 금지). `taken`은 Epic 5 — 만들지 않음.
- **격자:** `grid grid-cols-3 sm:grid-cols-4 gap-2`(모바일 3열·데스크톱 4열, `minmax(0,1fr)`로 넘침 방지). 접근 가능한 이름 한국어(예 `"10시 30분, 예약 가능"`/`"…, 선택됨"`), 색만으로 상태 구분 금지.
- **슬롯 생성(클라이언트, 30분 격자):**
```ts
function slotsForDay(day: Date, startH = 9, endH = 18) {
  const out: { label: string; iso: string }[] = [];
  for (let h = startH; h < endH; h++) for (const m of [0, 30]) {
    const d = new Date(day);
    d.setHours(h, m, 0, 0);                 // 초·ms 명시적으로 0
    out.push({ label: `${String(h).padStart(2,"0")}:${String(m).padStart(2,"0")}`, iso: d.toISOString() });
  }
  return out;                                // iso 는 항상 UTC(...Z)
}
```
`.toISOString()`은 로컬→UTC 변환이지만 **KST는 정시(UTC+9) 오프셋이라 분·초가 불변** → 로컬 :00/:30이 UTC에서도 :00/:30 → CHECK 통과. 백엔드는 받은 값을 `to_slot()`으로 재검증/floor. (단위 오프셋 tz(+5:30 등)에선 깨지지만 우리 대상 아님 — AD-3.)
