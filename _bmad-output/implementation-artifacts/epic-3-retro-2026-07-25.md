## 2. 잘된 점 (Successes)

1. **핵심 패턴이 복리로 작동** — 단일 CTE(= db 함수 하나) 설계가 3.1 → 3.2(처방 0..N) → 3.3(출력 스탬프)로 복잡도가 커지는 내내 **아키텍처 리팩터 0회**로 확장됨. Epic 2 교훈("패턴 복제가 깊어질수록 리뷰 부하 감소")이 확인·연장. 3.1 create-story가 "트랜잭션 설계 — 이 스토리의 심장" 절로 방식을 못 박아둔 효과(회고 액션 #4 이행).
2. **3에픽 묵은 모바일 검증 갭 해소** — 2.2·2.3·2.4 "3연속 미검증"으로 남았던 모바일 카드 분기를 3.1에서 Playwright 390×844로 최초 시각 실측(회고 액션 #5 달성), 3.2도 390/1280 실측. 확장 스크린샷 논리 폭 고정 한계를 닫음.
3. **코드리뷰가 실기능 버그를 근본 차단** — 3.2 int4 overflow는 UI 도달 가능한 진짜 버그였고, 각 caller(증상)가 아니라 서비스 가드 한 곳에서 근본 수정(`_DAYS_MAX` 경계, db 호출 전 400). patch 곡선 3 → 1 → 0로 계속 하강.
4. **부채 → 해소 루프가 실제로 닫힘** — ErrorState 승격이 "언젠가"가 아니라 5번째 사본이 될 시점(3.3)에 트리거돼 이행됨. 쌓기만 하지 않고 임계에서 정리.
5. **중간 스코프 추가를 프로세스가 또 흡수(3.3)** — 사용자 결정으로 정확히 스코핑(직원 전용·마지막 시각만·환자 경로 없음)해 클린 배포. 2.4에 이은 두 번째 성공적 중간 승격.
6. **적대적 사전 검증 레이어(3.1)** — 코드리뷰 전 3렌즈 워크플로가 visited_at UTC 정규화·textarea resize-y(모바일 가로 오버플로)·CAS null 가드를 선차단. lint/build/pytest가 못 잡는 계층.

## 3. 어려웠던 점 / 성장 영역 (Challenges)

1. **Codex 리뷰 외부 의존 단일 장애점 (3.2)** — Codex가 상류 503(circuit open)으로 미가동. 내장 3레이어(Blind·Edge·Acceptance)가 int4 버그를 대신 잡아 실질 누락은 없었지만, 필수 리뷰 게이트가 외부 도구 하나에 걸려 있음. (폴백 절차는 workflow.md step 4에 이미 명문화 — "Codex 장애 시 사용자 보고 후 진행".)
2. **deferred 꼬리표가 3에픽째 open** — "deferred 처리 시점 태깅"이 Epic 1부터 open인 채 부채는 13 → 30 → 48건. 주인 없는 일회성 액션은 안 됨 — Epic 1→2→3 **세 번 확인된 동일 패턴**. 부채 대부분은 중복 사본 계열(fetch-or-404 4사본 · CAS 409 문구 3사본 · `ensure_utc` 미공유 · pre-fetch 조인 폭).
3. **라이브 E2E 완전 자동화 갭 지속** — 3.3은 Playwright emulateMedia 대신 CSSOM 검사 + 인-프로세스 ASGI TestClient(uvicorn 상당)로 대체(frontend에 Playwright 미설치). 정직한 대체지만 "라이브 UI 버튼 → 네트워크 체인" 완주 자동화는 Epic 2부터 미해결.
4. **견고성 갭이 한 계열로 누적** — 무제한 배열/문자열 길이 · drug_id bigint overflow를 "P0 데모·인증 전 내부 도구" 사유로 일관 defer. 개별로는 타당하나 한 부류로 쌓이는 중(3.2 리뷰 Defer 3건 동근).

## 4. 핵심 교훈 (Key Insights)

1. **잘 고른 핵심 패턴은 복리다** — 단일 CTE 문 하나가 3스토리·증가하는 복잡도(0→N 처방·출력 스탬프)를 리팩터 0으로 버팀. 초기 설계 투자가 후반 스토리의 리뷰 부하·회귀 위험을 계속 낮춤.
2. **액션은 "구체 트리거"가 있어야 이행된다** — ErrorState는 "5번째 사본" 트리거로 완수, "언젠가 다 태깅"은 3에픽 연속 미이행. Epic 2 교훈("스토리 Task로 내장돼야 이행")이 3회차 확정. → **이번 회고의 결정: 재나열을 멈추고 부채를 명시 동결한다.**
3. **리뷰 게이트의 외부 도구 의존은 폴백이 필요하다** — 내장 3레이어가 이미 그 역할을 했고, 폴백은 workflow.md에 이미 문서화돼 있음. 신규 조치 불필요, 기존 절차 유지.
4. **Epic 3가 Epic 4를 선투자로 깔아둠** — `GET /medical-records`(appointment_id 필터) + 정규 `MedicalRecordOut`(flat 처방 리스트, AD-10)이 이미 라이브. Epic 4는 같은 엔드포인트에 `patient_id` 필터만 얹으면 됨.
