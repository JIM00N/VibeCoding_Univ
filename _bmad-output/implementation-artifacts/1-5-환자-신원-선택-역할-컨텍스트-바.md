# Story 1.5: 환자 신원 선택 & 역할 컨텍스트 바

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 환자,
I want 등록 환자 목록에서 본인을 골라 신원을 잡기를,
so that 이후 화면이 내 데이터만 보여준다(로그인 대체).

## Acceptance Criteria

**AC1 — 목록에서 본인 선택 → `patient_id` 컨텍스트 고정 (FR-2, AD-8)**
**Given** 첫 화면에서 `[환자]`를 선택했을 때
**When** 등록 환자 목록(Story 1.4의 `GET /patients` 재사용)에서 본인을 선택한다
**Then** 이후 환자용 조회 엔드포인트는 `?patient_id=`로 그 환자만 필터한다

> 📎 **이 스토리에서의 완료 판정:** 환자용 조회 엔드포인트(`GET /appointments?patient_id=` 등)는 **Epic 4**에서 생긴다. 1.5는 그 앞단 — **선택한 환자의 정수 `id`가 컨텍스트에 고정되고, 화면 이동·새로고침 뒤에도 그 값이 남아 Epic 4가 `?patient_id=`로 쓸 수 있는 상태**까지가 AC1이다. 없는 엔드포인트를 부르거나 만들지 말 것(§경계).

**AC2 — 컨텍스트 바가 역할·선택 환자·전환 액션을 유지 (UX-DR4)**
**Given** 환자 신원이 선택된 상태에서
**When** 화면을 이동하거나 새로고침한다
**Then** 상단 역할 컨텍스트 바가 현재 역할 + 선택 환자 + 전환 액션을 유지해 보여준다

**AC3 — 무인증 데모 고지 배너 (UX-DR8, AD-8)**
**Given** 환자 신원 선택 화면에서
**When** 진입한다
**Then** "데모라 누구나 선택 가능하며 보안 격리가 아님"을 알리는 고지 배너가 표시된다

### ⚠️ 신원 컨텍스트 설계 — 이 스토리의 심장 (실측 검증됨)

**요구:** 새로고침·화면 이동에도 선택 환자가 유지(AC2, UX-DR4: *"새로고침해도 컨텍스트 유지(로컬 상태/URL)"*). 저장소는 **`localStorage`**.

#### ❌ 함정 1 — `useEffect` + `setState` 재수화는 **린트 에러다** (추측 아님, 실측)
가장 자연스러운 코드가 이 레포에서 **빌드를 막는다**:
```tsx
useEffect(() => { setPatient(readStored()); setReady(true); }, []);  // ❌ npm run lint 실패
```
```
error  Calling setState synchronously within an effect can trigger cascading renders
       react-hooks/set-state-in-effect
```
1.4도 같은 규칙(`setLoading(true)`)에 걸려 우회했다(§이전 스토리 인텔리전스). React 19.2 + Next 16 의 이 규칙은 **경고가 아니라 error** — `npm run lint`가 깨진다.

#### ❌ 함정 2 — lazy `useState` 초기자 단독은 **하이드레이션 불일치**
```tsx
useState(() => localStorage.getItem(KEY))  // ❌ 서버=없음, 클라=있음 → mismatch
```
Next 16 공식 문서(`node_modules/next/dist/docs/01-app/02-guides/preventing-flash-before-hydration.md`)는 이 패턴을 **반드시 inline script + `suppressHydrationWarning`과 짝지으라**고 한다. 그 조합은 `dangerouslySetInnerHTML`까지 끌고 와서 이 스토리엔 과하다.

#### ✅ 정답 — `useSyncExternalStore` (린트·타입체크 통과 실측 완료)
localStorage 같은 **외부 저장소를 SSR 안전하게 구독**하는 React 공식 API. 린트 규칙에 안 걸리고, `getServerSnapshot`이 있어 하이드레이션 불일치도 없다. **아래 코드는 이 레포에서 `npx eslint`·`npx tsc --noEmit` 통과를 실측 확인했다 — 그대로 쓰라.**

```ts
// frontend/lib/patient-identity.ts
"use client";

import { useCallback, useSyncExternalStore } from "react";

export type PatientIdentity = { id: number; name: string };
type Snapshot = { ready: boolean; patient: PatientIdentity | null };

const STORAGE_KEY = "hospital-care.patient";
// 서버 렌더 스냅샷은 항상 "아직 모름"(ready:false). 상수 1개를 재사용해야 참조가 안정적이다.
const SERVER_SNAPSHOT: Snapshot = { ready: false, patient: null };

let cache: Snapshot = SERVER_SNAPSHOT;
let cachedRaw: string | null = null;
const listeners = new Set<() => void>();

function parse(raw: string | null): PatientIdentity | null {
  if (!raw) return null;
  try {
    const parsed = JSON.parse(raw);
    // 깨진 JSON·구버전 값이 화면을 죽이지 않게 shape 를 검증한다.
    if (typeof parsed?.id === "number" && typeof parsed?.name === "string") {
      return { id: parsed.id, name: parsed.name };
    }
    return null;
  } catch {
    return null;
  }
}

function getSnapshot(): Snapshot {
  let raw: string | null = null;
  try {
    raw = localStorage.getItem(STORAGE_KEY);
  } catch {
    raw = null; // 사생활 모드 등 — 앱을 죽이지 않는다.
  }
  // ⚠️ 값이 그대로면 이전 객체를 그대로 돌려준다. 매번 새 객체를 만들면 무한 렌더.
  if (!cache.ready || raw !== cachedRaw) {
    cachedRaw = raw;
    cache = { ready: true, patient: parse(raw) };
  }
  return cache;
}

const getServerSnapshot = (): Snapshot => SERVER_SNAPSHOT;

function subscribe(listener: () => void): () => void {
  listeners.add(listener);
  window.addEventListener("storage", listener); // 다른 탭에서의 변경도 반영
  return () => {
    listeners.delete(listener);
    window.removeEventListener("storage", listener);
  };
}

function emit() {
  for (const l of listeners) l(); // 같은 탭 변경은 storage 이벤트가 안 오므로 직접 알린다.
}

export function usePatientIdentity() {
  const snapshot = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot);

  const selectPatient = useCallback((p: PatientIdentity) => {
    try {
      localStorage.setItem(STORAGE_KEY, JSON.stringify({ id: p.id, name: p.name }));
    } catch {
      // 저장 실패해도 앱은 계속 돈다(이 세션 한정으로 동작).
    }
    emit();
  }, []);

  const clearPatient = useCallback(() => {
    try {
      localStorage.removeItem(STORAGE_KEY);
    } catch {
      // 무시
    }
    emit();
  }, []);

  return { ...snapshot, selectPatient, clearPatient };
}
```

**왜 Provider(`createContext`)가 아닌가:** 이 훅은 모듈 전역 스토어를 구독하므로 **Provider 없이 어느 클라이언트 컴포넌트에서든 바로 쓴다**. `layout.tsx`(서버 컴포넌트) 수정이 필요 없고, 직원 화면은 이 훅을 아예 안 쓴다. 파일 1개로 끝.

**`ready`의 의미(중요):** 서버 렌더·하이드레이션 첫 프레임엔 `ready:false`(아직 localStorage 를 못 읽음). `ready:false`를 **"신원 없음"으로 착각해 리다이렉트하면 안 된다** — 신원이 있는 사용자도 튕긴다. 반드시 `ready && !patient` 로 판정.

**저장 값이 `{id, name}` 둘 다인 이유:** 바가 이름을 보여줘야 하고(AC2) Epic 4는 id 로 부른다(AD-8). `id`만 저장하면 이름을 얻으려 `GET /patients/{id}`가 필요한데 **그런 엔드포인트는 없다**(만들지 말 것 — 백엔드 무변경). *한계(정직):* DB 에서 그 환자가 사라지면 저장된 이름이 낡을 수 있다 — 데모 범위로 수용, Epic 4에서 실데이터 조회 시 자연히 드러난다.

### 라우트·IA — 두 개의 surface

EXPERIENCE IA 는 **환자 신원 선택**과 **환자 홈**을 서로 다른 화면으로 못 박는다 [Source: EXPERIENCE.md#Information-Architecture]:

| 화면 | 라우트 | 이 스토리에서 |
|---|---|---|
| 환자 신원 선택 | `/patient/select` **(신규)** | 배너 + 목록 + 선택 |
| 환자 홈 | `/patient` **(기존, 가드 추가)** | 인사 + 바. 예약/기록 본문은 **4.1** |

- 명명은 1.4 선례(`/staff/patients` + `/staff/patients/new`)와 정렬 — 하위 세그먼트로 행위 분리.
- **`app/page.tsx`의 `[환자]` 버튼은 손대지 않는다**(`/patient` push 그대로). `/patient` 가드가 신원 없으면 `/patient/select`로 보내고, **신원이 이미 있으면 홈으로 바로 들어간다** — 이게 AC2 의 "유지"가 체감되는 지점이다.
- 가드는 `router.replace`(← `push` 아님). `push` 면 뒤로가기가 다시 가드로 들어가 튕김 루프가 된다.

### RoleContextBar 확장 (AC2)

현재 상태 [Source: frontend/components/role-context-bar.tsx]: `role`·`patientName?` props, `patientName` 있으면 `· {name}님` 표시, "역할 바꾸기"(`/`) 링크. **주석에 *"선택 환자 유지/전환은 Story 1.5 에서 확장"*이라고 적혀 있다 — 이 prop 은 지금을 위해 설계됐다.**

- **더할 것:** `patientName`이 있을 때만 "다른 환자" 링크(→ `/patient/select`). 그게 전부.
- **지킬 것:** props 시그니처. 이 바는 `staff/page.tsx`·`staff/patients/page.tsx`·`staff/patients/new/page.tsx` 3곳이 `role="직원"`으로 쓴다 → prop-driven 유지하면 **직원 화면 무변경**(회귀 0).

### 데모 고지 배너 (AC3, UX-DR8)

- **위치:** `/patient/select` 진입 시 **항상 보이게**(목록 로딩·오류·빈 상태와 무관하게 렌더 — 배너를 목록 성공 분기 안에 넣지 말 것).
- **문구(EXPERIENCE Voice 그대로):** *"지금은 로그인이 없어 누구나 목록에서 환자를 고를 수 있어요(데모)."* + 보안 격리가 아님을 덧붙인다(AD-8).
- **톤:** 정보 배너 — ❌ **destructive/red 금지**. DESIGN: *"red 는 오직 도메인 거부(슬롯 충돌·walk-in 빈 의사 없음)와 파괴적 확정(예약 취소)에만"*. 파괴적 액션이 아니다. `muted`/`secondary` 계열 `Card` 로 충분.
- 기존 `/patient/page.tsx`에 이 문구의 축소판이 **이미 Card 로 들어있다**(*"이 안내는 신원 선택 화면에서 배너로 확장돼요"*) → 그 Card 는 홈에서 **걷어내고** 선택 화면 배너로 옮긴다.

### 프런트 규약 & ⚠️ Next.js/shadcn 특이점

- **⚠️ 이 Next.js 는 훈련 데이터와 다르다(16.2.10).** `frontend/AGENTS.md`: *"코드 작성 전 `node_modules/next/dist/docs/`(특히 `01-app`)의 관련 가이드를 읽어라."* 이 스토리에 걸리는 문서: `02-guides/preventing-flash-before-hydration.md`(위 함정 2), `01-getting-started/05-server-and-client-components.md`.
- **⚠️ shadcn = `base-nova` style on `@base-ui/react`(Radix 아님).** 이 스토리는 **새 컴포넌트가 필요 없다** — `card`·`button`·`skeleton`으로 충분. 손으로 Radix import 금지.
- **환자 화면 밀도(DESIGN·UX-DR11):** 환자 = **단일 컬럼·여유 있는 카드**, `max-w-2xl`. ❌ 직원용 밀도 표(`Table`) 재사용 금지 — 같은 디자인 언어, 다른 밀도.
- **접근성(UX-DR9):** 환자 항목은 **`<button>`**(또는 `<Link>`) — ❌ `onClick` 달린 `<div>` 금지(키보드 도달 불가). 접근 가능한 이름에 이름+식별 정보를 담는다(동명이인 구분): 예 `aria-label="이수민, 1990-03-12 · 여 — 이 환자로 계속하기"`.
- **성별 역매핑 재사용:** DB `M`/`F`/null → `남`/`여`/`—`. 1.4가 `staff/patients/page.tsx`에 `genderText`/`orDash` 로 확정 [Source: frontend/app/staff/patients/page.tsx:27-35]. 같은 매핑을 쓴다(❌ `M`/`F` 원값 노출 금지). *(공용 모듈 추출은 선택 — 4.2에서 세 번째 사용처가 생기면 그때가 자연스럽다.)*
- **환자 톤 = 안심·친근한 해요체**(EXPERIENCE Voice). 인사는 display(28px/700) 1회만 — `"{이름}님, 안녕하세요"`.
- **상태 4색(대기/확정/완료/취소)은 여기 안 쓴다** — 환자 리소스엔 status 가 없다.

### 핵심 안티패턴 (하지 말 것)

- ❌ **`useEffect` + `setState` 로 localStorage 재수화** — 린트 error(실측 확인). `useSyncExternalStore`를 쓴다.
- ❌ **`getSnapshot`에서 매번 새 객체 반환** — 무한 렌더. 값이 같으면 같은 참조를 돌려준다(위 `cache`).
- ❌ **`ready:false`를 "신원 없음"으로 판정** — 신원 있는 사용자가 선택 화면으로 튕긴다. `ready && !patient`.
- ❌ **`localStorage` 접근을 try/catch 없이** — 사생활 모드/차단 환경에서 앱 전체가 죽는다. [Source: feedback-verify-browser-render]
- ❌ **백엔드 손대기** — 이 스토리는 프런트 전용. `GET /patients/{id}`·`?patient_id=` 엔드포인트를 **새로 만들지 말 것**(Epic 4 범위).
- ❌ **없는 환자용 조회 호출**(`GET /appointments?patient_id=` 등) — Epic 4에 없다. 404/에러만 낳는다.
- ❌ **환자 홈에 예약 목록·진료 기록 본문 구현** — Story 4.1 침범.
- ❌ **신원 선택 화면에 검색 인풋 추가** — AC 에 없다. 검색은 직원 도구(1.4). 데모 환자는 소수라 목록으로 충분(스코프 크립).
- ❌ **선택 화면 빈 상태에 "신규 환자 등록" 버튼** — 환자는 스스로 등록 못 한다(등록=직원 FR-4). 1.4 직원 빈 상태를 그대로 복사하지 말 것.
- ❌ **조회 오류를 빈 상태로 렌더** — 1.4 리뷰가 잡은 그 버그("백엔드 다운"을 "환자 없음"으로 오인). 오류는 별도 상태 + 다시 시도.
- ❌ **고지 배너를 red/destructive 로** — red 는 도메인 거부·파괴적 확정 전용(DESIGN).
- ❌ **`RoleContextBar` props 시그니처 변경**·바 안에서 컨텍스트 훅 호출 — 직원 화면 3곳 회귀.
- ❌ **`app/page.tsx`·`lib/api.ts`·`layout.tsx`·`main.py` 등 하드닝 완료 파일 수정** — 1.1~1.4가 굳혔다.
- ❌ **`db/seed/004_seed.sql` 재실행** — `truncate ... restart identity cascade` 로 기존 환자 유실. 이 스토리는 DB 를 안 건드린다.
- ❌ **컴포넌트에서 직접 `fetch`** — `lib/api.ts` 경유(AD-1, AD-10).
- ❌ **`patient_id`를 "보안"으로 표현** — 앱 레벨 필터일 뿐(AD-8). UI 문구가 기밀 보장을 암시하면 안 된다.
