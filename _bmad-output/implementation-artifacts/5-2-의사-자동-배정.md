## Story

As a 환자,
I want 담당 의사를 비워두면 그 진료과의 빈 의사가 자동 배정되기를,
so that 특정 의사를 고르지 않아도 예약이 잡힌다.

**한 줄 성격:** **백엔드 소폭 + 프런트 1화면.** 서버는 `POST /appointments`의 "의사 미선택 400" 가드를 자동 배정 분기로 대체한다 — 빈 의사 pick + INSERT를 **단일 CTE 문 하나**로(5.1 확립 관용구), pick 조각(`free_doctor_sql`)은 `db/availability.py`에 두어 **5.3 walk-in이 그대로 공유**한다(AD-4 "같은 헬퍼"의 이행). 프런트는 환자 예약 화면(`patient/book`)의 의사 Select에 "자동 배정" 옵션을 얹고, 자동 모드의 taken 사전 표시는 **기존 `GET /availability`를 과 의사별로 호출해 교집합**으로 계산한다(신규 엔드포인트 0). **대리 예약 다이얼로그는 UI 무변경**(FR-18은 FR-6 P0 재사용 명시 — 직원은 의사 지정이 기본). 신규 마이그레이션 0 · 신규 의존성 0 · 신규 파일 0(테스트 제외).

## Acceptance Criteria

**AC1 — 자동 배정 생성 (FR-6 P1)**
**Given** 진료과·슬롯을 선택하고 의사를 비워둔 채(`doctor_id` null 또는 필드 생략)
**When** `POST /appointments`를 제출한다
**Then** 그 진료과 의사 중 그 슬롯이 빈 의사를 **id 오름차순 1명** 골라 배정하고 `doctor_id`를 채워 201로 생성한다. pick과 INSERT는 **한 SQL 문**(`_INSERT_APPOINTMENT_AUTO`) — pick 시점과 삽입 시점이 갈라질 수 없다(AD-4 원자성, 5.1 관용구). 응답은 기존 `AppointmentOut` 그대로(`doctor_id`·`doctor_name` 채워짐 — AD-10 모델 무변경). 과거 시각 400 가드는 자동 경로에도 **선행**한다(db 일절 미호출 — 기존 가드 순서 유지).

**AC2 — 전원 점유·빈 과 거부 (FR-6 P1, UX-DR10)**
**Given** 그 진료과의 모든 의사가 그 슬롯에 점유됐을 때(활성 예약 ∪ walk-in 기록, 양변 floor — 5.1 union 판정 그대로)
**When** 자동 배정을 제출한다
**Then** **409** `{"detail": "이 시간엔 모든 의사의 예약이 차 있어요. 다른 시간을 골라 주세요."}` — 기존 두 409 문구(생성 충돌·의사 변경 충돌)와 **문구로 구분**된다(구분 assert 선례: test_appointments.py:930-933). 진료과에 의사가 0명이면 **400** `{"detail": "이 진료과엔 등록된 의사가 없어요. 다른 진료과를 골라 주세요."}`(점유가 아닌 요청 결함 — 409/400 구분 기준은 5.1 Dev Notes 그대로. 시드는 과당 2명이라 데모 도달 불가지만 500 방지).

**AC3 — 공유 헬퍼: 조각 1벌 유지 (AD-4, 에픽 AC3의 이행)**
**Given** 빈 의사를 찾는 로직이
**When** 구현된다
**Then** `free_doctor_sql(slot_sql)` 조각과 `NoFreeDoctorError` 예외를 **`app/db/availability.py`**(`SlotTakenError` 옆)에 두고, 5.3 walk-in이 같은 조각을 조합만 하도록 남긴다. 이를 위해 `OCCUPIED_SOURCES`·`slot_taken_sql`은 **의사 표현식 파라미터화**(`doctor_sql: str = "%(doctor_id)s"` 기본값)로 확장한다 — 기본값 경로의 생성 SQL은 기존과 **동일**하고(기존 3 소비자 무수정), union·floor 정의는 여전히 **정확히 한 벌**이다. floor 식(`SLOT_EXPR`)·`to_slot()`은 무수정(AD-3).

**AC4 — P0 경로 무수정 · 의도적 계약 변경은 1건뿐**
**Given** `doctor_id`를 지정한 기존 생성 경로·`PATCH /appointments/{id}/doctor`·`GET /availability`가
**When** 이 스토리가 끝난다
**Then** 검증 체인(과거 400 → 소속 검증 → FK) · 모든 기존 4xx 문구 · 응답 계약이 **바이트 무변경**이다. 의도적 계약 변경은 **`400 "담당 의사를 선택해 주세요."` 제거 1건**(에픽이 예고한 P0 강제의 P1 해제) — 이를 고정한 기존 테스트 `test_create_appointment_missing_doctor_rejected_korean_detail`(test_appointments.py:158-176) **1개만 교체**하고 나머지 기존 테스트는 무수정 green이다. 분기는 `if payload.doctor_id is None`(현행 falsy 검사 정밀화) — `doctor_id=0`은 자동 배정이 아니라 기존 `_require_doctor_in_department` 경로로 흘러 400 "담당 의사를 찾을 수 없어요. 다시 선택해 주세요."가 된다(크래프트 입력 한정 문구 변화 — 정직 기록). `insert_appointment`의 doctor_id None 명시 거부(ValueError)는 **그대로 유지** — 자동 배정은 별도 문이 담당한다.

**AC5 — 환자 화면: "자동 배정" 옵션 + 교집합 taken 표시 (UX-DR3, UX-DR7, UX-DR10)**
**Given** `patient/book`에서 진료과를 골랐을 때
**When** 의사 Select를 연다
**Then** **첫 항목 "자동 배정"**이 있고(빈 선택≠자동 — 미선택 제출은 지금처럼 인라인 에러 유지), 선택 시:
- **taken 사전 표시**: 그 과 의사 전원의 `GET /availability`를 병렬 호출해 **전원 점유 슬롯만** taken으로 렌더한다(교집합 — 한 명이라도 비면 예약 가능). 기존 slot-picker 3상태·범례·"이 날짜는 예약이 모두 찼어요" 안내가 그대로 동작한다. 부분 실패 포함 조회 실패는 비치명 — 이전 스냅샷 보존(5.1 P3 규율).
- **제출**: `doctor_id: null`로 POST. 성공 카드가 **배정된 의사 이름**을 표시한다(기존 `created.doctor_name ?? "담당 의사"` 렌더가 응답 값으로 자동 충족). 성공 시 그 슬롯 takenMs 추가+재조회(기존 대칭 유지).
- **409**: 기존 red 인라인(`role="alert"`, 서버 detail 그대로) + 그 셀 즉시 taken + 선택 해제 + 재조회 경로가 새 문구를 그대로 흡수한다(코드 분기 추가 0).
- **전환 잔상 0**: 자동↔특정 의사 전환은 기존 의사 변경 핸들러(동일값 가드 + `setTakenMs(null)`)를 그대로 지나 잔상이 없다(5.1 Med #2 동클래스 — 실측 필수).
- 요약 블록·문구는 자동 모드에서도 렌더된다(의사 자리 "자동 배정" 라벨). **옵션 라벨·표기 세부는 로컬 실측(:3000)에서 확정**한다.
- **대리 예약 다이얼로그 무변경** — 의사 선택 필수 그대로.

**AC6 — 회귀 0 · 품질 게이트**
**Given** 이 스토리가 생성 경로와 book 화면을 건드릴 때
**When** 검증한다
**Then** ① pytest 전체 green — 기존 테스트 무수정(AC4의 교체 1개 제외) + 신규 계약·단위 테스트, ② `npm run lint`·`npm run build` 그린, ③ **curl 실증**(실 Supabase): 자동 201·점유 의사 회피 pick·전원 점유 409·walk-in union 반영·과거 400 선행·빈 과 400·기존 지정 경로 회귀, ④ **브라우저 실측 book 화면만**(UI 변경이 여기뿐 — 390×844 + ≥md, 콘솔 0) — **"시간 경과"·"같은 값 재선택"·"자동↔직접 전환 잔상" 시나리오 필수**(Epic 6 회고 액션 #1·#2), ⑤ 검증 데이터 SQL 원복(기록→예약 순).

> 경계(정직): 동시 요청 경쟁(TOCTOU)은 5.1과 동일하게 범위 밖(단일 세션 전제 — 아키텍처 Deferred). 자동 pick의 원자성은 "한 문장 안"에서 성립하며, 문장 사이 경쟁(교집합 표시 스냅샷 vs 제출)은 서버 409가 최종 방어다. walk-in 생성(5.3)·부하 분산 pick·진료과 단위 가용성 API는 범위 밖 — 이 스토리는 조각을 세우고 생성 경로 하나에만 건다.

### 🎯 이 스토리의 한 줄 요약

**"의사 미선택 400"을 자동 배정으로 바꾸는 것이 전부다 — 빈 의사 pick은 5.1 조각의 조합이고, 프런트는 옵션 하나와 교집합 계산만 얹는다.** 서버 접촉면은 `create_appointment`의 분기 1곳 + db 문 1개, 프런트는 book 화면 1개. 5.3 walk-in이 `free_doctor_sql`·`NoFreeDoctorError`를 그대로 소비하도록 조각을 availability.py에 두는 것이 이 스토리의 인계 면이다.

### 구현 결정 3건 (대안 비교 완료)

1. **자동 배정은 별도 CTE 문(`_INSERT_APPOINTMENT_AUTO`), 기존 `insert_appointment` 확장 아님** — 5.1 리뷰 패치가 `insert_appointment`에 doctor_id None **명시 거부**(ValueError, db/appointments.py:229-233)를 "5.2 직접 호출자 대비"로 심어뒀다. 그 가드를 풀지 않는다: None 게이트 무력화 잠복을 막은 이유가 여전히 유효하고, 자동 경로는 pick이 검사 그 자체라 문장이 다르다. 대안(서비스가 빈 의사를 먼저 조회 후 기존 insert 호출)은 pick과 삽입 사이가 갈라져 기각 — "검사+쓰기 한 문장"이 이 프로젝트가 같은 문제에 채택한 이유다(Epic 2 회고 액션 #4 → 3.1 → 5.1).
2. **자동 모드 taken 표시는 기존 `GET /availability` N회 + 클라이언트 교집합, 진료과 단위 API 신설 안 함** — 5.1 계약 테스트가 `AvailabilityOut` 키셋(`{doctor_id, taken}`)을 고정했고, 과당 의사 수가 소수(시드 2명)라 N회 병렬 호출이 충분하다. 교집합(전원 점유 = ∩ taken)은 표시 전용이고 서버 409가 진실이라 발산 위험이 없다. 신규 엔드포인트·스키마 변경·db 범위 쿼리 전부 불필요해져 diff가 크게 준다. 의사 수가 커지면 그때 과 단위 API로 승격(deferred 기록).
3. **"자동 배정"은 명시 옵션, 빈 선택은 여전히 에러** — 에픽 원문 "비워두면"의 의도(의사를 고르지 않아도 예약 가능)는 명시 옵션으로 충족하면서, 실수로 미선택 제출 시 자동 배정되는 사고를 막는다(비관적 UX — 환자 화면 안심 톤). 미선택 인라인 에러("담당 의사를 선택해 주세요.")는 프런트 문구라 서버 계약과 무관하게 유지된다.

### SQL 청사진 (`db/availability.py` 확장 + `db/appointments.py` 신규 문)

```python
# availability.py — 의사 표현식 파라미터화(기본값 = 기존과 문자열 동일)
def occupied_sources_sql(doctor_sql: str = "%(doctor_id)s") -> str:
    return f"""
        select a.reserved_at as occupied_at
        from public.appointment a
        where a.doctor_id = {doctor_sql}
          and a.status in ('대기', '확정')
          and (%(exclude_appointment_id)s::bigint is null or a.id <> %(exclude_appointment_id)s)
        union all
        select m.visited_at
        from public.medical_record m
        where m.doctor_id = {doctor_sql}
          and m.appointment_id is null
    """

def slot_taken_sql(slot_sql: str, doctor_sql: str = "%(doctor_id)s") -> str: ...  # 기존 합성에 doctor_sql 전달만 추가

def free_doctor_sql(slot_sql: str) -> str:
    """진료과(%(hospital_department_id)s) 의사 중 slot_sql 슬롯이 빈 의사 1명(id 오름차순).
    5.2 자동 배정·5.3 walk-in 공유 — 재정의 금지."""
    return f"""(
        select d.id
        from public.doctor d
        where d.hospital_department_id = %(hospital_department_id)s
          and not {slot_taken_sql(slot_sql, doctor_sql="d.id")}
        order by d.id
        limit 1
    )"""

class NoFreeDoctorError(Exception):
    """진료과 전 의사 (슬롯) 점유 — 서비스가 409로 매핑한다. 5.3 walk-in 거부도 이 예외."""
```

```sql
-- db/appointments.py _INSERT_APPOINTMENT_AUTO (표시 조인은 _INSERT_APPOINTMENT 미러)
with free_doctor as (
    select fd.id from {free_doctor_sql("%(reserved_at)s")} fd
),
inserted as (
    insert into public.appointment (patient_id, hospital_department_id, doctor_id, reserved_at, status)
    select %(patient_id)s, %(hospital_department_id)s, fd.id, %(reserved_at)s, '대기'
    from free_doctor fd
    returning id, patient_id, hospital_department_id, doctor_id, reserved_at, status
)
select exists (select 1 from free_doctor) as free_found,
       i.id, i.patient_id, i.hospital_department_id, i.doctor_id, i.reserved_at, i.status,
       p.name as patient_name, doc.name as doctor_name, d.name as department_name
from (select 1) one
left join inserted i on true
left join public.patient p on p.id = i.patient_id
left join public.hospital_department hd on hd.id = i.hospital_department_id
left join public.department d on d.id = hd.department_id
left join public.doctor doc on doc.id = i.doctor_id
```

- **`insert_appointment`의 doctor_id None ValueError 가드를 풀지 말 것** — 자동 배정은 `_INSERT_APPOINTMENT_AUTO` 소유. 가드는 5.1 리뷰가 심은 잠복 방지다.
- **union·floor·free pick 조각을 두 번째로 적지 말 것** — `occupied_sources_sql`/`slot_taken_sql`/`free_doctor_sql`은 availability.py 한 벌. `_INSERT_APPOINTMENT_AUTO`는 조합만 한다. 5.3도 마찬가지.
- **`GET /availability`에 진료과 파라미터를 추가하지 말 것** — 키셋 고정 계약(5.1 테스트). 교집합은 클라이언트 몫(구현 결정 2).
- **부하 분산·랜덤·라운드로빈 pick 금지** — `order by d.id limit 1` 결정적 pick. 에픽 AC는 "빈 의사를 골라"만 요구한다.
- **proxy-booking-dialog에 자동 배정을 이식하지 말 것** — FR-18은 FR-6 **P0** 재사용 명시(직원은 의사 지정이 기본). 서버는 이미 클라이언트 무관하게 자동을 지원하므로 필요해지면 UI만 얹는 별도 스토리.
- **walk-in(5.3)을 미리 만들지 말 것** — red Dialog 거부·medical_record 생성은 5.3 소유. 이 스토리는 `free_doctor_sql`·`NoFreeDoctorError`를 세워두기만 한다.
- **빈 선택을 자동 배정으로 해석하지 말 것** — 미선택 제출은 기존 인라인 에러 유지(구현 결정 3).
- **기존 4xx 문구·가드 순서를 1바이트도 바꾸지 말 것** — 의도적 변경은 "미선택 400" 제거 1건뿐(AC4). 테스트를 고쳐 green 만들지 말 것 — 교체 1개 외 기존 테스트 무수정이 동작 보존의 증명이다.
