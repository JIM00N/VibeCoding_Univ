## Story

As a 접수 직원/의사(직원 화면),
I want 완료된 진료의 처방전을 별도 화면에서 조회하고 브라우저로 출력하며 출력 여부·마지막 출력 시각을 확인하기를,
so that 환자에게 종이 처방전을 건네고, 출력했는지를 나중에 확인할 수 있다.

**범위 결정(2026-07-24 사용자 확정):** 처방전은 **직원 전용** 문서다. 처방전은 약국 제출용 통제 문서(위·변조·중복 사용 방지, 사용기간 기재, 병원이 교부·재발급 통제)라 환자 조회·출력 경로를 만들지 않는다 — 환자는 병원(직원)에 요청해 종이로 받는다. 환자의 처방 **내역** 확인(무슨 약을 받았는지)은 Story 4.1(FR-11 — 진단·처방 포함 조회)이 담당한다.

## Acceptance Criteria

**AC1 — 저장 직후 처방전 직행 + 완료·출력 상태 한 화면 확인 (FR-10 확장, UX-DR2)**
**Given** 처방이 1건 이상인 진료 기록을 저장했을 때(3.2 기록 폼)
**When** 저장이 성공한다
**Then** 성공 toast 후 목록 대신 `/staff/appointments/[id]/prescription`(처방전 화면)으로 이동한다 — **처방 0건 저장은 기존대로 목록 복귀**(3.2 동작의 의도적 개정, 이 스토리가 소유)
**And** 처방전 화면에 예약 **완료** 배지(`AppointmentStatusBadge`, 실제 예약 상태)와 출력 상태(미출력/마지막 출력 시각)가 함께 표시된다

**AC2 — 처방전 조회: 완료 행 재진입 + 시트 렌더 (FR-10 확장, AD-10)**
**Given** 완료 상태의 예약(진료 기록·처방 보유)이 있을 때
**When** 예약 목록의 **완료 행에만** 노출되는 `[처방전]`(Link)으로 진입한다
**Then** `GET /medical-records?appointment_id=`(신규, `list[MedicalRecordOut]` 0..1행)로 기록·처방을 로드해 처방전 시트(환자·진료과·담당 의사·진료 일시·처방 표(약/용법·용량/일수)·출력 상태)를 렌더한다
**And** 진료 기록이 없으면 "이 예약의 진료 기록이 없어요.", 처방 0건이면 "처방이 없는 진료예요. 처방전을 출력할 수 없어요." 안내(각각 목록 복귀 제공)를 시트 대신 보여준다

**AC3 — 출력: 서버가 시각을 기록한 뒤 인쇄, 인쇄물엔 시트만 (AD-9, AD-10)**
**Given** 처방전 화면에서
**When** `[처방전 출력]`을 누른다
**Then** `POST /medical-records/{record_id}/print`(body 없음, 200)가 `prescription_printed_at = now()`를 기록하고 갱신된 정규 모델을 반환한 뒤 브라우저 인쇄가 열린다 — **시각은 SQL `now()`만 소유**(클라이언트·서비스가 시각을 보내지 않는다, db 함수 인자에 시각 없음이 계약)
**And** POST 실패 시 toast 만 띄우고 인쇄를 진행하지 않는다(이력 없는 출력 금지)
**And** 인쇄 화면에는 처방전 시트만 나온다(역할 바·버튼·안내는 `print:hidden`)

**AC4 — 출력 여부·시각 확인 + 재출력 갱신**
**Given** 출력한 적이 있는/없는 처방전에서
**When** 화면을 본다
**Then** 미출력이면 "아직 출력하지 않았어요.", 출력했으면 "마지막 출력: {Asia/Seoul 시각}"이 표시되고, 재출력하면 최신 시각으로 갱신된다(출력 여부 = `prescription_printed_at` not null)
**And** `MedicalRecordOut`에 `prescription_printed_at: datetime | None`이 추가돼 **모든 medical-records 엔드포인트가 같은 모양**을 반환한다(생성 직후 null 포함, AD-10)

**AC5 — 서버 가드·회귀 0 + 품질 게이트**
**Given** 부적격 요청일 때
**When** 서버에 도달한다
**Then** print 는 없는 기록 **404** "진료 기록을 찾을 수 없어요." · 처방 0건 **400** "처방이 없는 진료 기록이에요."(거부 경로에서 UPDATE 미호출), GET 은 `appointment_id` 누락 **422**(FastAPI 필수 쿼리)
**And** 3.1·3.2의 기록 작성 가드 체인·완료 전이·처방 저장이 그대로 동작하고(회귀 0), 백엔드 `pytest` 그린 — **기존 테스트 수정은 `MedicalRecordOut` 모양 변경이 강제하는 최소 수정뿐**(3.2가 만든 키셋 단언·`_fake_record_row`에 `prescription_printed_at` 추가 — dev 시점에 위치 특정해 Dev Agent Record 에 기록). 프런트 `npm run lint`·`npm run build` 그린

## Dev Notes

### 🎯 이 스토리의 한 줄 요약

`medical_record`에 **컬럼 하나**(`prescription_printed_at`)를 더하고, medical_records 3계층에 **읽기(GET by appointment)와 도장 찍기(POST print)** 를 add-only 로 얹은 뒤, 직원 전용 처방전 페이지가 "저장 직후 직행 + 완료 행 재진입" 두 경로로 열린다. 출력이라는 **행위**가 이력을 만든다(버튼 클릭 → 서버 now() 기록 → 인쇄). **환자 쪽은 아무것도 만들지 않는다** — 내역 조회는 Epic 4 몫.

### 설계 근거 (사용자 확정 결정 3건 — 2026-07-24)

1. **출력 이력 = 마지막 출력 시각만.** 컬럼 1개(`timestamptz NULL`)로 "출력 여부(= not null) + 언제(= 값)"를 다 답한다. 출력 로그 테이블은 만들지 않는다(감사 추적이 필요해지면 그때 `prescription_print_log` 로 승격 — 업그레이드 경로만 기록).
2. **저장 직후 직행.** 실제 데스크 흐름(진료 → 즉시 출력 → 교부). 3.2가 확정한 "저장 → 목록 복귀"를 **처방 ≥1건일 때만** 개정한다 — 완료 배지 확인은 처방전 화면의 상태 배지가 대신한다(목록을 안 거치므로).
3. **환자 경로 없음.** 처방전은 병원이 교부를 통제하는 문서(중복 조제·위변조 방지, 사용기간). 환자의 "무슨 약 받았지" 는 Story 4.1 의 진료 기록 조회(처방 포함)가 정답 — 3.2가 정규 모델에 처방을 넣어둬 4.1 은 추가 비용이 없다. 무인증 데모라 URL 직접 접근 자체는 막지 못한다(AD-8 기존 한계와 동일 — 새 구멍이 아님).

- 4번째 마이그레이션이지만 **파일 번호는 005**(004 는 시드가 선점). 기존 001~003 스타일 미러(주석 + 단문).

### SQL 청사진 — 읽기 2종 + 도장 1종 (db/medical_records.py add-only)

**① `_SELECT_RECORDS_BY_APPOINTMENT`** (GET 용 — 3.2 CTE 최종 SELECT 의 투영을 독립 SELECT 로 미러):

```sql
select mr.id, mr.appointment_id, mr.patient_id, mr.hospital_department_id,
       mr.doctor_id, mr.visited_at, mr.diagnosis, mr.notes,
       mr.prescription_printed_at,
       p.name   as patient_name,
       doc.name as doctor_name,
       d.name   as department_name,
       coalesce(
           (select jsonb_agg(jsonb_build_object(
                'id', pr.id, 'drug_id', pr.drug_id, 'drug_name', dr.name,
                'dosage', pr.dosage, 'days', pr.days) order by pr.id)
            from public.prescription pr
            join public.drug dr on dr.id = pr.drug_id
            where pr.medical_record_id = mr.id),
           '[]'::jsonb) as prescriptions
from public.medical_record mr
join public.patient p               on p.id  = mr.patient_id
join public.hospital_department hd  on hd.id = mr.hospital_department_id
join public.department d            on d.id  = hd.department_id
join public.doctor doc              on doc.id = mr.doctor_id
where mr.appointment_id = %s
order by mr.id
```

**② `fetch_medical_record(record_id)`** — 같은 투영에 `where mr.id = %s` 만 다른 사본(print 가드용). 사본 2개는 refdata `_SELECT_DOCTORS`/`_BY_HD` 컨벤션 준수 — 공유 fragment 정리는 기존 deferred("표시 조인 SQL 사본")에 합류.

**③ `_MARK_PRESCRIPTION_PRINTED`** (print 용 — UPDATE 가 시각을 소유):

```sql

       doc.name as doctor_name,
       d.name   as department_name,
       coalesce( (…①과 동일한 처방 집계 서브쿼리, u.id 기준…), '[]'::jsonb) as prescriptions
from updated u
join public.patient p               on p.id  = u.patient_id
join public.hospital_department hd  on hd.id = u.hospital_department_id
```

- **왜 3.1 처럼 CAS 가 없나(주석으로 남길 것):** 기록·처방에는 삭제/수정 API 가 없어 검증과 UPDATE 사이에 상태가 바뀔 경로가 없고, `printed_at` 덮어쓰기는 멱등이다(두 번 눌러도 최신 시각). 3.1 의 CAS 는 status 전이 경합용 — 여기 복제하지 말 것.
- `mark_prescription_printed(record_id) -> dict | None` — **시각 인자를 받지 않는 시그니처가 계약**(서버 시각 단일 소스, AD-6 의 "클라이언트 미신뢰" 정신). 0행(None)은 없는 기록 — 서비스 404 방어.

### 서비스 — 신규 2함수 (기존 `create_medical_record` 가드 체인 ①~⑥ 무변경)

```python
def list_medical_records(appointment_id: int) -> list[MedicalRecordOut]:
    rows = medical_records_db.fetch_medical_records_by_appointment(appointment_id)
    return [_to_medical_record_out(row) for row in rows]

def print_prescription(record_id: int) -> MedicalRecordOut:
    current = medical_records_db.fetch_medical_record(record_id)
    if current is None:
        raise HTTPException(status_code=404, detail="진료 기록을 찾을 수 없어요.")
    if not current["prescriptions"]:
        raise HTTPException(status_code=400, detail="처방이 없는 진료 기록이에요.")
    row = medical_records_db.mark_prescription_printed(record_id)
    if row is None:  # 삭제 API 부재로 도달 불가 — 방어(위 404 문구 재사용)
        raise HTTPException(status_code=404, detail="진료 기록을 찾을 수 없어요.")
    return _to_medical_record_out(row)
```

- GET 은 필터드 목록이라 0행 = `[]`(404 아님 — patients/appointments 목록 계약 미러). "기록 없음" 해석은 프런트 몫. **epics AC 의 "서버도 4xx 거부"는 print 경로에 한정하는 의도적 정밀화다**(조회는 빈 목록+안내가 목록 계약 정합 — 이 스토리가 소유하는 해석, epics 에도 반영됨).
- `_to_medical_record_out` 에 `prescription_printed_at=row["prescription_printed_at"]` 1줄 추가 — 매핑은 계속 한 곳.

### 라우터 (AD-2 — HTTP 만)


### 프런트 화면 설계 (`/staff/appointments/[id]/prescription`)

- **로드:** 마운트 effect(기존 `setTimeout(…,0)` 패턴)에서 `getAppointment(id)` + `getMedicalRecords(id)` 병렬(`Promise.all`) — 어느 쪽이든 실패 시 ErrorState(재시도+목록 복귀). 성공 후: 기록 0행 → NoticeState "이 예약의 진료 기록이 없어요." / 처방 0건 → NoticeState "처방이 없는 진료예요. 처방전을 출력할 수 없어요."
- **시트(인쇄 대상 영역):** Card 안에 — 제목 `처방전`(h1 은 페이지, 시트 내부는 문서 헤더 스타일) · 환자명 · 진료과 · 담당 의사 · 진료 일시 · 처방 표(칼럼: 약 / 용법·용량 / 일수 — `dosage`·`days` null 은 `—` 표시). 병원명·진단명 미표시(위 결정).
- **시트 밖(화면 전용, 전부 `print:hidden`):** RoleContextBar 래퍼 · **페이지 h1·부제(제목 블록 — 시트 내부 문서 헤더와 중복 인쇄 방지)** · 예약 상태 배지 줄(`확정→완료` 미리보기가 아니라 **현재 상태 배지 하나**) · 출력 상태 줄 · 액션 버튼들 · 안내 문구. 인쇄물에 남는 것은 시트 Card 하나뿐이어야 한다(AC3 — emulateMedia 로 실측).
- **출력 상태 줄:** `prescription_printed_at` null → "아직 출력하지 않았어요."(muted) / 값 있음 → "마지막 출력: {formatReservedAt(printed_at)}".
- **출력 버튼:** `submittingRef` 가드 → `printPrescription(record.id)` → `setRecord(갱신 행)` → `setTimeout(() => window.print(), 0)`(React 배칭 뒤 인쇄 — 다이얼로그가 갱신된 DOM 을 보게) / 실패 → `toast.error(detail)`, 인쇄 안 함. **인쇄 완료 여부는 웹에서 알 수 없다** — "출력 = 버튼 클릭 시점 기록"이 정직한 계약(주석으로 명시).
- **반응형:** 시트는 단일 컬럼 max-w-2xl(기록 페이지 미러). 처방 표는 `≥md` 표·모바일 스택(UX-DR11), 390px 가로 오버플로 금지.
- **a11y:** 출력 상태는 텍스트(색 의존 없음), 버튼 라벨 명시, 표 헤더 `<th>` — UX-DR9 바닥 유지.

### 마이크로카피 (UX-DR10 — 직원=간결 해요체)

- 목록 액션: `처방전` · 페이지 제목: `처방전` · 부제: `진료에서 처방한 약을 확인하고 출력해요.`
- 버튼: `처방전 출력`(primary) · `예약 목록으로`(ghost) · 출력 중: `출력 준비 중…`
- 상태: `아직 출력하지 않았어요.` / `마지막 출력: {시각}`
- 안내: `이 예약의 진료 기록이 없어요.` · `처방이 없는 진료예요. 처방전을 출력할 수 없어요.`
- 로드 실패: `처방전을 불러오지 못했어요.` + `다시 시도`
- 서버: 404 `진료 기록을 찾을 수 없어요.`(**신규 문구** — 기존 "예약을 찾을 수 없어요." 404 스타일 미러, 코드베이스에 아직 없음) · 400 `처방이 없는 진료 기록이에요.`
- 표 빈 값: `—` · ❌ 습니다체·이모지·영문 금지.

### 핵심 안티패턴 (하지 말 것)

- ❌ **클라이언트가 출력 시각을 보내기 / 서비스가 `datetime.now()` 생성** — 시각은 SQL `now()` 단일 소스. db 함수 시그니처에 시각 인자를 넣는 순간 계약 위반.
- ❌ **print 에 CAS·트랜잭션 합성 복제** — 경합 대상이 없다(수정/삭제 API 부재, 멱등 덮어쓰기). 3.1 패턴의 관성 복제 금지.
- ❌ **인쇄 성공을 감지하려는 시도**(`afterprint` 로 기록 등) — 브라우저는 실제 인쇄 여부를 알려주지 않는다. 버튼 클릭 = 기록이 정직한 계약.
- ❌ **POST 실패 후 인쇄 진행** — 이력 없는 출력물 금지(AC3).
- ❌ **환자 화면에 처방전 진입점·라우트 추가** — 사용자 확정 OUT. 4.1 이 내역 조회로 커버.
