## 2. 잘된 점 (Successes)

1. **미리 깔아두기 전략이 두 번 크게 통함**

   - 1.4가 `GET /patients`를 1.5용으로 미리 설계(검색 없으면 전체) → 1.5가 백엔드 변경 0으로 재사용.
2. **계층 규약(AD-2)의 매끄러운 복제** — 1.1이 세운 refdata 3계층(routers→services→db)을 1.3·1.4가 거의 복사만으로 확장. 재사용이 스토리마다 가팔라짐.
3. **눈으로 확인하는 검증 문화** — 5개 스토리 전부 헤드리스 브라우저 스크린샷으로 실제 렌더까지 확인하고 마감.
4. **적대적·독립 리뷰** — 1.5의 `memoryRaw` 폴백 버그를 4개 출처(BMad 3계층 + Codex 독립 모델)가 잡아냄.

## 3. 어려웠던 점 / 성장 영역 (Challenges)

1. **"done"인데 미배포 (가장 중요)** — Story 1.5가 sprint-status·스토리 문서상 `done`이었지만, 코드가 커밋조차 안 된 워킹트리 변경이었고 라이브에 없었다. 라이브 `/patient/select`는 404, `/patient`는 1.5 이전 자리표시였다. **이번 회고의 라이브 검증에서 발견 → 커밋·배포로 해결.**
2. **최신 스택 반복 함정** — React 19 + Next 16의 `set-state-in-effect`가 경고가 아닌 **오류**라 1.4(로딩)·1.5(신원 재수화)에서 두 번 빌드를 막음. shadcn이 base-nova/@base-ui(Radix 아님)라는 훈련데이터 불일치도 매 스토리 경고 필요.
3. **"수정 완료" 선언이 반쪽짜리였던 사건 (1.5)** — dev 단계에서 폴백 버그를 "고침"이라 적었으나 실제론 대칭 케이스만 덮음. "스펙이 시켰다"는 순환 방어는 무효(스펙을 같은 에이전트가 씀).
4. **공유 DB 검증 데이터 누적** — 1.3·1.4 검증 중 만든 테스트 환자가 공유 Supabase에 12명 잔존.

---

## 4. 핵심 교훈 (Key Insights)

1. **"done ≠ 커밋 ≠ 배포"** — 세 가지는 다른 상태다. 완료 판정에 라이브 확인을 넣어야 갭이 안 생긴다.
2. **적대적·독립 리뷰가 단일 검증이 놓치는 것을 잡는다** — 특히 "부분 실패" 모드는 전부-아니면-전무 테스트로는 안 잡힌다.
3. **미리 깔아두기(정직한 확장 지점)가 후속 스토리를 가볍게 만든다.**
4. **최신 스택의 반복 함정은 스토리 인텔리전스로 전수해 관리한다.**
