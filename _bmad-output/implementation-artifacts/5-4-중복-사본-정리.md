# Story 5.4: 중복 사본 정리 (프런트 헬퍼·백엔드 서비스 블록 수렴)

Status: review

## Story

As a 개발팀(5.2 자동 배정·5.3 walk-in 을 곧 얹을),
I want 프런트·백엔드에 흩어진 중복 사본을 각 정본 한 벌로 수렴하기를,
so that 같은 로직의 수정이 한 곳에서 끝나고, 이미 시작된 사본 간 드리프트(formatReservedAt 방어 가드)가 멈추며, 5.2·5.3 이 깨끗한 정본 위에 얹힌다.

## Acceptance Criteria

1. **AC1 — book 화면 헬퍼 수렴 (booking-slots 2-소스 · formatReservedAt 2-소스 종결)**
   **Given** `frontend/app/patient/book/page.tsx` 의 로컬 헬퍼 블록(33-101행: `HOSPITAL_TZ`·`HOSPITAL_UTC_OFFSET`·`seoulTodayYmd`·`slotsForSeoulDay`·`formatReservedAt`·`formatSeoulDayLabel`·`seoulDayOptions`)
   **When** 블록을 통째로 삭제하고 `@/lib/booking-slots`(슬롯 3함수)·`@/lib/format`(formatReservedAt) import 로 교체한다
   **Then** 화면 동작·표시가 동일하고(슬롯 격자·날짜 라벨·성공 카드 시각), `formatReservedAt` 은 정본의 "—" 방어 가드 방향으로 통일된다(사본에만 없던 가드 — 유일하게 허용되는 동작 차이).

2. **AC2 — orDash 4사본 → `lib/format.ts` 승격**
   **Given** 바이트 동일한 `orDash` 4사본(patient/select:25 · staff/patients:35 · staff/patients/[id]:37 · proxy-booking-dialog:53)
   **When** `lib/format.ts` 에 `orDash` 를 export 로 추가(add-only)하고 4곳을 import 로 교체한다
   **Then** 로컬 정의 0, 표시 동일("—" 폴백 포함).

3. **AC3 — ErrorState 로컬 6사본 → `components/error-state.tsx` 이관**
   **Given** 정본(`components/error-state.tsx`)은 `onBack` 이 **필수**이고 로컬 6사본(doctor:293 · doctor/select:144 · patient/select:166 · staff/patients:202 · staff/appointments:515 · staff/appointments/[id]/record:503)은 대부분 `{message, onRetry}` 뿐일 때
   **When** 정본의 `onBack` 을 **옵션**으로 바꾸고(미전달 시 뒤로 버튼 미렌더 — 기존 4개 호출부는 전부 onBack 을 넘기므로 무영향) 6사본을 import 로 교체한다
   **Then** 각 화면 렌더 결과가 지금과 동일하다 — **onBack 없던 5화면에 뒤로 버튼을 새로 만들지 않는다**. record 페이지(유일하게 onBack 보유)는 기존 onBack 유지(backLabel 기본값 "예약 목록으로" = 현 문구 그대로).

4. **AC4 — 백엔드 fetch-or-404 4사이트 · CAS 409 문구 3사이트 수렴**
   **Given** "예약을 찾을 수 없어요." 404 블록 4곳(services/appointments.py:104-106·146-148·183-185, services/medical_records.py:47-49)과 "예약 상태가 방금 바뀌었어요…" 409 문구 3곳(appointments.py:164·227, medical_records.py:117)
   **When** `services/appointments.py` 에 공개 헬퍼 `fetch_appointment_or_404(appointment_id) -> dict` 와 상수 `CAS_CONFLICT_DETAIL` 을 만들어 전 사이트가 사용한다(medical_records 는 services.appointments 에서 import — 순환 없음)
   **Then** 4xx 문구가 **바이트 동일**하게 유지되고, 문구를 고정한 기존 계약 테스트가 **무수정으로** green 이다.

5. **AC5 — naive→UTC 정규화 3-인라인 → `ensure_utc()` 공유 헬퍼**
   **Given** 같은 2줄 정규화가 3곳(slots.py:19-20 의 to_slot 내부, medical_records.py:84-86, availability.py:16-19 — 5.1 이 "공유 헬퍼 승격은 정리 스토리 몫"으로 예고)
   **When** `app/slots.py` 에 `ensure_utc(dt) -> datetime`(naive→UTC 간주 + `astimezone(utc)`)을 추가하고 3곳이 사용한다(`to_slot` 도 내부에서 재사용)
   **Then** to_slot·기록 저장·availability 조회의 시각 계약이 불변이고(기존 테스트 무수정 green), 5.3 의 walk-in `visited_at` 이 쓸 정본이 준비된다.

6. **AC6 — 잔여 소사본 2건 (같은 성격·저위험)**
   **Given** `_blank_str_to_none` 2사본(schemas/medical_records.py:9 ↔ schemas/patients.py:23)과 의사↔진료과 검증 블록 2-소스(services/appointments.py:60-67 ↔ 197-204, 문구 2종 바이트 중복)
   **When** 검증자는 `schemas/patients.py` 의 공개 함수로 승격해 medical_records 가 import 하고, 검증 블록은 같은 파일 안에서 `_require_doctor_in_department(doctor_id, hospital_department_id)` 로 추출한다
   **Then** 400 문구 바이트 동일·기존 테스트 무수정 green.

7. **AC7 — book 슬롯 라벨 a11y (deferred-work 가 "헬퍼 정리와 함께 처리"로 못 박은 건)**
   **Given** book/page.tsx:480 의 짝 없는 `<Label id="slot-label">`(htmlFor 없는 실제 `<label>` — DevTools a11y 이슈)
   **When** 6.3 픽스 패턴(proxy-booking-dialog:704 의 `<span id …>`)을 이식해 `<span id="slot-label">` 로 바꾼다(동일 클래스 유지, `ariaLabelledBy="slot-label"` 체인 무변경)
   **Then** DevTools "No label associated with a form field" 이슈 0, radiogroup 접근 이름 유지, 시각 표시 동일.

8. **AC8 — 무회귀 실증 (이 스토리의 존재 이유가 "동작 불변"이다)**
   **Given** 정리 완료 상태
   **When** 전체 검증을 돌린다
   **Then** ① pytest 전체 green — **기존 116개 무수정**(ensure_utc 단위 테스트만 신규), ② `npm run lint`·`npm run build` 그린, ③ 사본 grep 0건(아래 Task 6 명령), ④ curl 실증은 **거부·조회 경로만**(404 3경로·naive availability 200·과거 400 — 데이터 생성 0 → **원복 0**), ⑤ 브라우저 실측(book 화면 흐름 + ErrorState 강제 렌더, 콘솔 0), ⑥ 신규 마이그레이션·의존성·기능·API 변경 0.

### 구현 결정 — 수렴처 선택의 이유

- **백엔드 공유 홈을 새로 만들지 않는다**: `fetch_appointment_or_404`·`CAS_CONFLICT_DETAIL` 은 `services/appointments.py` 에 둔다 — 예약 서비스가 status·예약 로드의 소유자(AD-5)고, medical_records 는 이미 개념상 appointments 에 의존한다(services→services import, 순환 없음: appointments 는 medical_records 를 모른다). 신규 `common.py`/`errors.py` 모듈은 만들지 않는다(파일 최소).
- **`ensure_utc` 의 홈은 `app/slots.py`**: 시각 규약(AD-3)을 이미 소유한 모듈. availability 서비스의 5.1 주석("공유 ensure_utc 헬퍼 승격은 중복 사본 정리 스토리 몫")이 이 결정을 예고했다. 시맨틱 주의: naive→UTC 간주 + aware→`astimezone(utc)`. medical_records 의 현 인라인은 astimezone 이 없지만 **인스턴트는 동일**(aware +09:00 이든 UTC 표현이든 timestamptz 저장 결과가 같다) — 표현 정규화일 뿐 동작 차이가 아니다.
- **`blank_str_to_none` 의 홈은 `schemas/patients.py`**: 최초 정의 지점이자 더 기저 스키마. medical_records→patients import 는 단방향(역방향 의존 없음). 신규 모듈 불필요.
- **ErrorState 는 "옵션화"가 이관의 열쇠**: 정본의 `onBack` 필수 시그니처를 그대로 두면 5화면에 뒤로 버튼이 **신설**돼 UI 가 바뀐다(이 스토리의 금기). 옵션화는 기존 4개 호출부(전부 onBack 전달)에 무영향인 add-only 완화다.
- **formatReservedAt 드리프트는 정본 방향으로**: 정본에만 있는 "—" 가드는 리뷰에서 의도적으로 넣은 방어(Invalid Date 노출 방지). 사본 제거 = 가드 통일이 곧 개선이라 예외적으로 "동작 차이"가 허용되는 유일 지점(비정상 입력 경로 한정).
- **회고 액션 #5 명시 6건 + deferred-work 가 이 스토리로 라우팅한 3건(CAS 409·짝 없는 label·ensure_utc) + 같은 성격 저위험 2건(#8·#9)이 전체 스코프다.** #8·#9 는 회고 명시 목록 밖 확장이니 리뷰에서 이의가 있으면 그 2건만 되돌리면 된다(독립 커밋 권장).
