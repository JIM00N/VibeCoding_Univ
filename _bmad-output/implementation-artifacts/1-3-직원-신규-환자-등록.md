# Story 1.3: 직원 신규 환자 등록

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **접수 직원**,
I want **신규 환자를 이름·생년월일·성별·연락처로 등록하기를**,
so that **처음 온 환자를 시스템에 올려 이후 예약·진료로 이을 수 있다.**

> Epic 1의 **세 번째 스토리**이자 **첫 쓰기(write) 기능**이다. 1.1·1.2가 세운 3계층 뼈대(브라우저 → FastAPI → Supabase) 위에서 **첫 도메인 리소스(`POST /patients`)를 관통시킨다**. 지금까지는 읽기(`GET /departments`)만 있었다 — 이 스토리가 앱이 실제로 DB에 행을 **쓰는** 첫 경로를 연다.
>
> ⚠️ **범위 경계(scope guard):** 이 스토리는 **환자 "등록"(POST)만** 만든다. 환자 **목록·검색**(`GET /patients`, `?search=`)은 **Story 1.4**, 환자 **신원 선택·컨텍스트 바**는 **Story 1.5**, 예약은 **Epic 2**다. 목록 화면을 여기서 만들지 말 것(1.4 침범). "등록 후 즉시 사용 가능"의 관찰 증거는 **성공 toast + POST 응답의 정규 모델**이며, 목록 렌더가 아니다.

## Acceptance Criteria

> 원본 BDD: [Source: _bmad-output/planning-artifacts/epics.md#Story-1.3]

**AC1 — 환자 생성 + 정규 응답 모델**
- Given 직원 화면의 환자 등록 폼에서
- When 이름(필수)·생년월일·성별·연락처를 입력하고 저장한다
- Then `POST /patients`로 환자가 생성되고, 응답이 **리소스 정규 모델**(정수 `id` + 평평한 표시 필드: `name`·`birth_date`·`gender`·`phone`)로 온다 `(FR-4, AD-10)`

**AC2 — 이름 필수 검증(인라인 + 서버 백스톱)**
- Given 이름이 비어 있을 때(빈 문자열·공백만 포함)
- When 저장을 시도한다
- Then 프런트가 **라벨된 인라인 오류**로 제출을 먼저 막고, 서버에 도달해도 **4xx `{"detail": "..."}`(한국어 문자열)**로 거부한다 `(AD-10, UX-DR9)`

**AC3 — 성공 피드백 + 즉시 사용 가능**
- Given 등록에 성공했을 때
- When 저장이 끝난다
- Then **성공 toast**를 띄우고, 생성된 환자가 **이후 목록/신원 선택(1.4·1.5)에서 즉시 사용 가능**하도록 DB에 영속된다(관찰 증거 = 성공 toast + POST 201 응답, 목록 렌더 아님) `(UX-DR7)`

### 실측 DB 스키마 — `patient` 테이블 (Supabase `fphsxoweprztrekckzui`, live baseline, AD-9)
> **이것이 진실의 원본.** [Source: 1-1-로컬-수직-슬라이스.md 실측 스키마]

| 컬럼 | 타입·제약 |
|---|---|
| `id` | `bigint` NOT NULL, **`GENERATED ALWAYS AS IDENTITY`** (앱은 넣지 않음, DB가 생성) |
| `name` | `text` **NOT NULL** ← 유일한 필수값 |
| `birth_date` | `date` **nullable** |
| `gender` | `text` **nullable** (CHECK 없음 — 시드는 `'M'`/`'F'` 사용) |
| `phone` | `text` **nullable** |

**스키마 함정(반드시 각인):**
1. **`id`는 `GENERATED ALWAYS AS IDENTITY`** → INSERT에 id를 넣으면 **에러**. id 없이 INSERT하고 `RETURNING id`로 받는다. 시드의 `setval`이 시퀀스를 max(3)에 맞춰뒀으니 다음 앱 INSERT는 id=4부터. (시드 주석: *"안 하면 이후 앱의 일반 INSERT가 id=1부터 생성해 PK 충돌 — Story 1.3 환자 등록에서 터짐"* — 그 함정을 시드가 이미 막아놨으니 평범한 INSERT면 안전.)
2. **name만 NOT NULL** — birth_date·gender·phone은 전부 nullable. 빈 값은 `null`로 저장(빈 문자열 `""` 저장 지양 → validator로 coerce).
3. **RLS ON이어도 백엔드는 소유자 역할로 우회** → INSERT 정상 동작. anon 정책 불필요(AD-7, 1.2에서 9테이블 RLS ON 실증됨).

### 성별(gender) 값 규약 — 이 스토리가 도메인을 확정한다
- gender는 **CHECK 없는 자유 text nullable**. 시드는 `'M'`(박지훈)·`'F'`(이수민·최유진)를 썼다. 이 스토리가 **환자를 쓰는 첫 코드**이므로 여기서 규약을 못 박는다.
- **결정(기본값):** DB에는 **`'M'`/`'F'`/`null`**만 저장(시드와 일관 → Story 4.2 직원 조회에서 표시 정합). UI Select는 **남/여**를 보여주고 제출 시 남→`'M'`, 여→`'F'`, 미선택→`null`로 매핑. 표시(4.2)에서 `'M'`→남, `'F'`→여로 역매핑.
- ❌ **하지 말 것:** UI 라벨(`'남'`/`'여'`)을 그대로 DB에 저장 — 시드(`'M'`/`'F'`)와 갈라져 조회 화면이 값이 섞인다.

### API 계약 (AD-10) — 이 스토리가 따르는 형태
- 경로 **복수형**: `POST /patients`. 성공 = `PatientOut` JSON 그대로(커스텀 봉투 없음), 생성이므로 **201**.
- 오류 = HTTP status + `{"detail": ...}`. 도메인/검증 거부는 **4xx + 한국어 문자열** detail.
- ⚠️ **detail은 반드시 "문자열"** — Pydantic 422의 detail은 리스트/객체라 `lib/api.ts`가 *"요청 내용을 확인해 주세요."* 일반 메시지로 바꾼다(친절한 문구 안 나감). 이름 검증처럼 **좋은 한국어 문구를 보이려면 서비스에서 `HTTPException(400, detail="이름을 입력해 주세요.")`**로 던진다(문자열 detail). 이게 AC2의 "4xx {detail} 한국어"를 정확히 만족한다.
- 연관 없음(patient는 FK 없음) — flat 표시 필드만. id는 정수, 날짜는 ISO(`date` → `"YYYY-MM-DD"`).

### 계층 규약 (AD-1·AD-2) — 위반 = 리뷰 반려
- **DB 커넥션은 `app/db/` 계층에서만** 연다. 라우터·서비스에서 커넥션 열기 금지. `routers`=HTTP·검증, `services`=비즈니스 규칙(이름 trim·검증)·트랜잭션 소유, `db`=유일한 SQL I/O.
- **상향 import 금지**(db가 services/schemas를 import하지 않음). refdata db가 `PatientOut`을 모르듯, patients db도 dict만 반환하고 서비스가 `PatientOut`으로 매핑.
- 프런트는 **`lib/api.ts`만** 통해 호출. 컴포넌트에서 직접 `fetch` 금지(AD-1, AD-10).

### 프런트 규약 & ⚠️ Next.js/shadcn 특이점
- **⚠️ 이 Next.js는 훈련 데이터와 다르다.** `frontend/AGENTS.md`: *"APIs·conventions·file structure가 다를 수 있으니 코드 작성 전 `node_modules/next/dist/docs/`(특히 `01-app`)의 관련 가이드를 읽어라."* 폼은 `page.tsx`처럼 **`"use client"` + `useState` + `api` 호출** 패턴을 따르면 안전(이미 동작하는 참조 구현).
- **⚠️ shadcn = `base-nova` style on `@base-ui/react`(Radix 아님).** `components.json` 확인됨. 컴포넌트는 반드시 `npx shadcn@latest add ...`로 생성(손으로 Radix import 넣지 말 것). 현재 `button`·`card`만 있음 → `input label select sonner` 추가 필요.

### 이전 스토리 인텔리전스 (1.1·1.2에서 이어받는 것)
- **1.1 리뷰 패치가 검증한 것:** `lib/api.ts`가 이미 성공/실패·빈 본문·비-JSON·네트워크 실패를 한국어로 견고화 → `createPatient`는 이 `request` 헬퍼만 재사용하면 그 견고함을 공짜로 얻는다.
- **1.2 리뷰 교훈:** 전역 예외 핸들러가 인프라 500을 한국어 `{detail}`로 매핑(CORS 헤더까지). 도메인 거부(이름 없음)는 그와 별개로 **4xx `{detail}`**로 서비스가 명시적으로 던진다 — 500(인프라)과 4xx(도메인) 경로가 다름을 혼동하지 말 것.
- **검증 문화(사용자 선호·메모리):** "완료"는 테스트 통과 + **브라우저에서 눈으로 관통 확인**(헤드리스 스크린샷). 1.1·1.2 모두 이 방식으로 마감. [Source: feedback-verify-browser-render]
- **커밋 이력:** 1.1(스캐폴딩)→1.2(배포·핸들러·CORS 패치). 이 스토리는 그 위 첫 도메인 CRUD. `main` 브랜치 기준.
