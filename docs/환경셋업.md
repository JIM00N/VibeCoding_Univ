# 환경 셋업 (hospital-care)

새 컴퓨터·새 클론에서 로컬 개발 환경을 세우는 절차. **이 문서의 모든 명령은 2026-07-27에 실제로 실행해 확인했어요**(부록 참고).

> 왜 이 문서가 있나 — Epic 2·3·6 회고에서 3에픽 연속 밀린 액션입니다. 실제로 시간을 잡아먹은 함정 세 개(**직접 호스트 IPv6 전용 · psql 미설치 · `load_dotenv()` 경로**)를 여기서 끝냅니다.

---

## 0. 이미 셋업된 사람용 3줄

```bash
# 백엔드 :8000 — 반드시 backend/ 안에서 (아래 3절 ⚠️ 참고)
cd backend && uv run --with-requirements requirements.txt --no-project python -m uvicorn app.main:app --port 8000

# 프런트 :3000
cd frontend && npm run dev
```

확인: `curl localhost:8000/health` → `{"status":"ok"}` · 브라우저 http://localhost:3000

## 3. `.env` 만들기 ← 여기가 핵심

### backend/.env

```bash
cd backend && cp .env.example .env
```

그리고 `DATABASE_URL`을 채웁니다. 값 얻는 법: **Supabase Dashboard → Connect → Session pooler** 문자열을 복사하고 `[YOUR-PASSWORD]` 자리에 DB 비밀번호를 넣어요.

지금 쓰는 형태(비밀번호만 가림):

```
DATABASE_URL=postgresql://postgres.fphsxoweprztrekckzui:<비밀번호>@aws-1-ap-northeast-2.pooler.supabase.com:5432/postgres
CORS_ORIGINS=http://localhost:3000
```

**⚠️ 왜 `db.<ref>.supabase.co`(직접 호스트)를 안 쓰나 — IPv6 전용이라서예요.**
Story 2.3 때 새 맥북에서 연결이 안 돼 진단에 시간을 썼습니다. 직접 호스트는 IPv6 주소만 있어서, IPv6 경로가 없는 네트워크에서는 붙지 않아요. Railway(IPv4)도 같은 이유로 실패합니다. 그래서 **로컬·배포 모두 Session 풀러(`…pooler.supabase.com:5432`, 사용자 `postgres.<project-ref>`)** 를 씁니다.

**포트는 5432(Session 모드) 권장.** 6543(Transaction 모드)은 psycopg3의 자동 prepared statement와 충돌해 간헐 오류가 나요. 앱은 `app/db/pool.py`에서 `prepare_threshold=None`로 방어하고 있지만, 굳이 6543을 쓸 이유가 없습니다.

**⚠️ 반드시 `backend/` 안에서 실행하세요.** `app/config.py`의 `load_dotenv()`는 **실행 위치(CWD) 기준**으로 `.env`를 찾습니다. 레포 루트에서 서버나 스크립트를 돌리면 `.env`를 못 찾아 이렇게 죽어요:

```
RuntimeError: DATABASE_URL 이 설정되지 않았습니다. backend/.env 에 값을 넣으세요(.env.example 참고).
```

### frontend/.env.local

```
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

- 파일이 없어도 동작해요 — `lib/api.ts`가 `http://localhost:8000`을 기본값으로 씁니다.
- **`NEXT_PUBLIC_` 값은 브라우저 번들에 그대로 박힙니다.** DB 문자열·비밀번호를 여기에 절대 넣지 마세요(AD-1/AD-7). 프런트가 아는 유일한 백엔드 좌표는 이 URL 하나입니다.
- 두 `.env` 파일 다 루트 `.gitignore`로 제외돼 커밋되지 않아요.

```bash

# ④ 프런트 (frontend/ 에서)
```

`/health`는 DB를 건드리지 않아요. **DB 연결 확인은 `/departments`로** 하세요. 참고로 서버는 기동 시점에 커넥션 풀을 열어보므로, `DATABASE_URL`이 틀리면 첫 요청이 아니라 **기동할 때 바로** 실패합니다.

## 5. psql 없이 DB 직접 만지기 (검증 데이터 원복)

이 맥에는 `psql`이 없어요. Epic 6에서 원복 SQL을 바로 못 돌린 원인입니다. **설치하지 않고** 쓸 수 있는 방법이 세 가지 있고, 아래 순서로 권합니다.

### ① uv + psycopg 한 방 (권장 · 설치 0 · `backend/` 에서)

```bash
cd backend
uv run --with 'psycopg[binary]' --with python-dotenv --no-project python -c "
import os, psycopg
from dotenv import load_dotenv
load_dotenv()
with psycopg.connect(os.environ['DATABASE_URL']) as conn, conn.cursor() as cur:
    cur.execute('select count(*) from public.appointment')
    print('예약 건수:', cur.fetchone()[0])
"
```

원복(삭제)도 같은 틀에 SQL만 바꿔 넣으면 돼요:

```python
    cur.execute('delete from public.appointment where id in (42, 43)')
    print('삭제:', cur.rowcount)
```

- `with psycopg.connect(...)` 블록이 정상 종료되면 **자동 커밋**됩니다(예외가 나면 롤백).
- 조회는 `cur.fetchall()`. `--no-project`가 있어야 uv가 이 폴더를 파이썬 프로젝트로 오해하지 않아요.

### ② Supabase MCP (Claude Code 안에서)

`.mcp.json`에 등록돼 있어 `execute_sql`·`apply_migration`로 바로 돌릴 수 있어요. 대화 중 원복할 땐 이게 제일 빠릅니다.

### ③ Supabase Dashboard → SQL Editor

브라우저에서 붙여넣고 실행. 마이그레이션 최초 적용에도 씁니다.

> psql이 꼭 필요하면 `brew install libpq` 후 PATH에 추가(`/opt/homebrew/opt/libpq/bin`)하면 돼요. 지금까지 필요했던 적은 없습니다.

**원복 규율:** 삭제 순서는 **처방 → 기록 → 예약**(FK 역순), 항상 **id 지정 삭제**. 시드 재실행으로 되돌리려는 시도는 금지예요.

## 7. 자주 나는 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| `RuntimeError: DATABASE_URL 이 설정되지 않았습니다` | 레포 루트 등 `backend/` 밖에서 실행 · `.env` 없음 | `cd backend` 후 실행 · `.env.example` 복사 |
| 연결 타임아웃 / `Network is unreachable` | 직접 호스트(IPv6 전용) 사용 | 풀러 호스트(`…pooler.supabase.com:5432`)로 교체 |
| prepared statement 관련 간헐 오류 | 포트 6543(Transaction 모드) | 5432(Session 모드)로 교체 |
| `No module named pytest` | 시스템 python3(3.11) 직접 호출 | uv 경유 명령 사용 |
| 브라우저 콘솔 CORS 차단 | `CORS_ORIGINS` 미설정 | `http://localhost:3000` 넣고 서버 재시작 |
| 화면은 뜨는데 목록이 계속 오류 | 백엔드 미기동 · `NEXT_PUBLIC_API_BASE_URL` 오타 | `curl localhost:8000/departments` 로 먼저 확인 |
| 라이브 502 | Railway 포트 정렬 깨짐 | 6절 ⚠️ 참고 |

## 8. 절대 하지 말 것

1. **`db/seed/004_seed.sql` 재실행** — TRUNCATE CASCADE로 예약·진료 기록·처방이 전부 날아가요(공용 라이브 DB).
2. **RLS anon 정책 추가** — 정책 0개(deny-by-default)가 의도된 설계입니다(AD-7).
3. **`.env` / `.env.local` 커밋** — 값은 Supabase·Vercel·Railway 대시보드가 원본.
4. **루트 `{output_folder}/` 손대기** — BMAD 설치 잔재예요. 실제 산출물은 `_bmad-output/`.
